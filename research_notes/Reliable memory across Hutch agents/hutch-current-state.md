## 1. What persistence and context machinery already exists?

### Takeaway

Hutch already owns a substantial SQLite conversation, reference-memory, and execution-evidence store. The useful next investment is consistent, runtime-independent context delivery and recovery contracts—not a second chat database. This recommendation follows the existing layered-memory decision and actual admission path. [Sources: ADR-0008](../../docs/adr/0008-memory-and-bounded-collaboration.md), [Store.submit_conversation_message](../../src/hutch/store.py#L5035-L5307).

### Cited Findings

**Authority:** Read current [AGENTS.md](../../AGENTS.md), [PRODUCT.md](../../PRODUCT.md), [continuation ledger](../../docs/realignment/ledger.md), and ADRs [0003](../../docs/adr/0003-durable-state-and-honest-outcomes.md), [0007](../../docs/adr/0007-external-runtimes.md), [0008](../../docs/adr/0008-memory-and-bounded-collaboration.md), [0011](../../docs/adr/0011-shared-usage-reservations.md), [0013](../../docs/adr/0013-recoverable-transcript-files.md), [0017](../../docs/adr/0017-governed-mcp-integration-plane-and-context-scaffolding.md), [0019](../../docs/adr/0019-cost-guardrails-context-continuity-and-routing.md). These are not uniformly current: ADR-0007's October 22 opening enables OpenCode, while its October 8 section still says no external executor is supported. ADR-0017 explicitly labels its older “no compaction” audit historical. Current code takes precedence over those stale descriptions.

SQLite uses WAL, `synchronous=FULL`, transactional writes, serialized upgrades and SQLite-backup-API migration snapshots. These mechanisms already address much of “own our history reliably”; they do not certify power-loss behavior on arbitrary storage. A Run's `conversation_context` is excluded from normal model JSON serialization but persisted in a dedicated SQL column and restored by `Store._run`. [Sources: Store initialization/migrations](../../src/hutch/store.py#L2385-L2486), [Run model](../../src/hutch/models.py#L599-L649), [Store._run](../../src/hutch/store.py#L3962-L3975).

**Partial output is not a uniform resumable stream.** Builtin retains selected provider-error partial text and output-limit text as `message` events marked `incomplete`; its first stream-recovery attempt is separately reserved and need not emit the discarded partial. OpenCode retains length-truncated text, but otherwise polls completed messages. Importantly, `_insert_events` projects any assistant content into `messages` without carrying `incomplete`/reason fields. Later bounded role/content context can therefore present partial text without its original qualification. This is a concrete continuity hazard, not evidence that stored events vanished. [Sources: builtin error handling](../../src/hutch/runtime/builtin.py#L1463-L1489), [OpenCode completion](../../src/hutch/runtime/opencode.py#L496-L559), [projection](../../src/hutch/store.py#L8248-L8263).

**Compaction exists, but cannot recover material already excluded at admission.** `fitloop` preserves coherent assistant/tool units, bounded exact user anchors selected by deterministic signals, and rejects non-shrinking summaries; unknown windows return `unknown_window` and proceed best-effort. Anchors are extracted from the supplied message list, not all canonical history. Hosted summaries default to review-required `ask`, use the current route, no tools, and separate usage reservations. Manifest-write failure is logged rather than fatal. These are derived context records, not authoritative effect receipts or general execution checkpoints. [Sources: fitloop](../../src/hutch/runtime/fitloop.py#L121-L246), [summary admission/recording](../../src/hutch/runtime/builtin.py#L905-L1108).

### Inferences

Keep conversations, facts, task obligations, and execution evidence distinct within the existing authority. Better persistence alone cannot make a model use omitted information, and summarization cannot prove that an action succeeded. The existing FTS/history paths offer a practical foundation before embeddings or a separate memory service. [Basis: layered decision](../../docs/adr/0008-memory-and-bounded-collaboration.md), [history queries](../../src/hutch/store.py#L4836-L4955), [honest-outcomes decision](../../docs/adr/0003-durable-state-and-honest-outcomes.md).

### Gaps

Tests were **read, not run**. Relevant regression anchors include `test_terminal_drain_commits_reply_and_history_atomically`, `test_conversation_context_budget_keeps_the_newest_turns`, event-outbox process-restart/competing-store tests, and compaction overflow/off/unknown-window tests. JSONL crash-after-fsync and competing-delivery tests exist. No fresh durability, live-provider, or power-loss result is claimed. [Sources: conversations](../../tests/test_conversations.py#L779-L824), [event outbox](../../tests/test_store_events.py#L80-L145), [runtime compaction](../../tests/test_runtime_compaction.py), [transcript mirror](../../tests/test_transcript_mirror.py).

## 2. Which runtimes and agents actually receive which memory?

### Takeaway

Builtin hosted providers and Ollama share Hutch's context/tool pipeline; OpenCode does not. Same-Bot children, named specialist tasks, and reusable cross-Bot grants are three different boundaries, so “all agents share memory” would be false. [Sources: builtin assembly](../../src/hutch/runtime/builtin.py#L1110-L1165), [OpenCode execution](../../src/hutch/runtime/opencode.py#L395-L431), [delegation contract](../../docs/realignment/delegation.md).

### Cited Findings

**Builtin:** starts with operator/system guidance, applicable bounded receipt guidance, saved `run.conversation_context`, and the current prompt. Both hosted and Ollama routes receive that assembled list through `ChatRequest`; Ollama additionally has explicit local window/resource admission. Ordinary fact text is not injected automatically: `remember` proposes; `recall` returns reviewed data only when exposed and invoked. Tool-free conversation/rewrite/draft modes have no ordinary memory tools. [Sources: assembly](../../src/hutch/runtime/builtin.py#L1110-L1165), [request](../../src/hutch/runtime/builtin.py#L1444-L1457), [route preparation](../../src/hutch/runtime/builtin.py#L418-L445), [memory tools](../../src/hutch/tools/memory.py), [tool-free guard](../../src/hutch/engine.py#L693-L700).

**OpenCode's actual continuity contract:**

- `_session_for` keys a JSON mapping file by hashed **conversation ID**, falling back to run ID. It stores `bot_id`, provider, model and session ID, but reuse checks only provider/model equality and remote session existence—not stored Bot identity, workspace, policy/instruction revision, or a last-synchronized Hutch message cursor. It is not a composite SQLite session binding. [Source](../../src/hutch/runtime/opencode.py#L46-L83), [reuse logic](../../src/hutch/runtime/opencode.py#L269-L290).
- `_prompt_text` returns only `run.prompt` for an existing session. A new/lost/model-changed session reads `list_conversation_messages(limit=60)`, removes one text-matching user row, formats each row to 4,000 characters, then takes the last 40 of those rows. That Store query is ascending: long chats bootstrap from the **first 60**, not the newest 60. Removal is text-based rather than exact message/run identity. [Sources: prompt](../../src/hutch/runtime/opencode.py#L244-L267), [ascending query](../../src/hutch/store.py#L4836-L4848).
- It never consumes `run.conversation_context`: selected task-only facts, explicit reply references and specialist-result attachments carried there are omitted. `execute` discards Hutch Tool objects; native capabilities derive from Bot tools, and the private config declares empty MCP/plugins. There is no supported `remember`/`recall` bridge. [Sources: execute](../../src/hutch/runtime/opencode.py#L395-L431), [agent exclusions](../../src/hutch/runtime/opencode.py#L100-L147), [private config](../../src/hutch/runtime/opencode_server.py#L58-L70).
- Switching OpenCode → Builtin → the same OpenCode route can reuse an old native session without syncing intervening Hutch turns. Switching models/session loss creates a bootstrap, but the old-page bug and missing context selections remain. Hutch's visible canonical history survives; model-visible continuity does not necessarily survive. These are static control-flow deductions, not reproduced live failures. [Basis: runtime selection](../../src/hutch/runtime/__init__.py#L16-L26), [worker selection](../../src/hutch/engine.py#L277-L307), [session/prompt logic](../../src/hutch/runtime/opencode.py#L244-L290).

**Fact lifecycle and scope:** model writes derive conversation/run scope from the persisted run, with lease/fence/cancellation/terminal checks. Human proposals also require review. Immutable revisions include content hash and provenance; review binds exact content and scope, with conflicting decisions rejected and exact retries retained. Creating a newer proposal hides the prior approved revision from new recall until the new revision is approved. [Sources: propose/page/review](../../src/hutch/fact_memory.py#L69-L268), [revision/fence tests](../../tests/test_fact_memory.py#L235-L279).

Bot-wide promotion (`review(..., action="share")`) creates an approved Bot-scope copy and archives its source; an existing nonarchived Bot-wide key conflicts. Named cross-Bot sharing instead stores one immutable source-fact snapshot for one recipient. Recall requires the source to remain current/approved and both Bots' memory enabled; either participant can revoke. Updated source facts require fresh review/grant. Incoming facts retain source attribution rather than becoming recipient-owned truth; the merge does not semantically resolve conflicting keys across sources. [Sources: promotion](../../src/hutch/fact_memory.py#L247-L267), [incoming filters](../../src/hutch/fact_memory.py#L162-L197), [share/recall/revoke](../../src/hutch/store.py#L9137-L9295).

Recall is literal bounded FTS5 (up to ten query terms), at most 20 tool-visible records/about 6,000 serialized characters, labelled potentially stale reference data. Disabling memory removes tools and stale tool instances recheck the persisted setting. Revocation affects future recall; already-returned tool text, running model messages, frozen handoffs and provider copies are not retroactively erased. [Sources: retrieval](../../src/hutch/fact_memory.py#L122-L197), [tool bounds/recheck](../../src/hutch/tools/memory.py#L47-L77), [revocation contract](../../docs/realignment/delegation.md#reusable-owner-granted-bot-references).

**Delegation and checkpoints:**

- Same-Bot `delegate_task` requires supervised Builtin Strict Offline execution and explicit outward approval. Children inherit bounded root capabilities, receive task text only and private workspaces, and lose memory/browser tools; final child text returns to the parent. Schema-v72 parked-parent continuations persist exact messages, call identity, model/tool/system hashes and deadline; resumption waits for child-tree/process cleanup and revalidates the contract. [Sources: delegated policy/execution](../../src/hutch/engine.py#L702-L892), [saved/restored model state](../../src/hutch/runtime/builtin.py#L1337-L1374), [checkpoint payload](../../src/hutch/runtime/builtin.py#L1807-L1823), [Store continuation](../../src/hutch/store.py#L7053-L7186).
- Named coordinator tasks create independent specialist conversations under the specialist's reviewed settings. Up to eight selected current reviewed coordinator facts/6,000 serialized characters are frozen into `workspace_task_fact_shares` and the initial run context; source revisions do not rewrite that frozen snapshot. They are not specialist durable memory, nor automatically carried into every later specialist turn. Selected result return is a separate explicit, attributed, bounded reference. [Sources: submit_workspace_task](../../src/hutch/store.py#L5470-L5649), [result attachment](../../src/hutch/store.py#L5120-L5259), [handoff regression](../../tests/test_conversations.py#L998-L1263).
- Ordinary crash recovery fences ownership, verifies cleanup and ends interrupted work as failed or `outcome_unknown`; it does not resume an arbitrary model loop. Named-task safe continuation permits one owner-confirmed **new** attempt only for a narrow no-effect Builtin case, excluding previously selected facts. Separately, workflow instances persist node results and admit bounded new orchestration attempts; this is not general chat recovery. [Sources: engine recovery](../../src/hutch/engine.py#L1354-L1418), [safe continuation](../../src/hutch/store.py#L5791-L5999), [workflow continuation](../../src/hutch/engine.py#L1584-L1634).

### Inferences

Memory parity needs an explicit adapter contract, not a claim that native session persistence equals Hutch memory. OpenCode tool execution remains under the user's OS authority, outside Builtin bubblewrap containment. Prompt scope labels cannot sandbox it. Its tool events also do not traverse Hutch's `begin_action`/`finish_action` receipt bracket. [Basis: ADR-0007](../../docs/adr/0007-external-runtimes.md#decision), [OpenCode tool observation](../../src/hutch/runtime/opencode.py#L369-L397), [receipt authority](../../src/hutch/store.py#L8054-L8108).

### Gaps

Do not hide unrelated adapter limits behind a memory project: OpenCode reserves once for estimated internal turns, settles that reservation on the first usage-bearing completion, and accounts later messages separately; its prompt API sends no per-generation cap. Step limits are checked after completed messages arrive. Native edit/write decisions may auto-pass Hutch's gate; `once` is not proof of a fresh human review. Transport failure during prompt submission is treated as rejection/released usage although acceptance could be ambiguous. These need dedicated failure tests, not promises of per-model hard budgets, universal fresh approvals, or globally exactly-once effects. [Sources: reservation](../../src/hutch/runtime/opencode.py#L292-L316), [dispatch/accounting](../../src/hutch/runtime/opencode.py#L435-L559), [prompt payload](../../src/hutch/runtime/opencode_server.py#L314-L322), [approval auto behavior](../../src/hutch/approvals.py#L79-L146).

Existing OpenCode tests use a fake server for completion, truncation, permission replies and disappearance; they do not establish native-session context parity. Fact revocation/restart, stale instances, same-Bot waits and no-effect continuation have focused fixtures, all unrun here. [Sources: OpenCode tests](../../tests/test_runtime_opencode.py#L27-L239), [facts](../../tests/test_fact_memory.py), [parked waits](../../tests/test_delegated_wait.py), [safe continuations](../../tests/test_delegation.py#L94-L176).

## 3. What should a self-contained implementation prompt require?

### Takeaway

Make the existing Store the runtime-independent authority and native sessions disposable execution caches. Deliver one failure-tested slice at a time; add schema only where an existing authority cannot represent the required contract. This is a planning recommendation, not implemented behavior. [Basis: existing admission](../../src/hutch/store.py#L5035-L5307), [layer separation](../../docs/adr/0008-memory-and-bounded-collaboration.md).

### Cited Findings

Reuse the current tests and authority above; preserve the distinction between persisted execution state, selected reference data, and lossy summaries. ADR-0017's future `task_state`/composer proposal overlaps this work but is not a shipped ordinary-chat memory system. Keep task progress in the existing realignment authority, with this research note as evidence rather than a competing project-memory source. [Sources: ADR-0017 status and planned S5/S6](../../docs/adr/0017-governed-mcp-integration-plane-and-context-scaffolding.md), [existing ledger](../../docs/realignment/ledger.md).

### Inferences — prioritized slices and candidate acceptance criteria

1. **A1: One deterministic context snapshot contract.** Reuse admission context, add source-message identities/high-watermark, provenance, explicit selections, truncation and incomplete-output qualifications. Both runtime adapters must consume the same authorized content. Fake-provider assertions should prove newest corrections survive a >60-message chat, current input appears once, selected facts/results/replies arrive, and unrelated chats/Bots never appear. Restart must reconstruct identical selections. [Starting seams](../../src/hutch/store.py#L4836-L4904), [OpenCode mismatch](../../src/hutch/runtime/opencode.py#L244-L267).

2. **A2: Native-session reconciliation.** Persist versioned bindings/synchronization state in the existing Store; define Bot/conversation/route/workspace/policy affinity. Test missing mapping, deleted native session, model A→B→A, Builtin↔OpenCode changes, repeated text, queued turns and restart between prompt admission/acknowledgement. Uncertain acceptance requires reconciliation, never blind resend. No blanket claim of provider-side exactly-once delivery. [Starting seams](../../src/hutch/runtime/opencode.py#L269-L290), [dispatch ambiguity](../../src/hutch/runtime/opencode.py#L435-L494).

3. **A3: Supported scoped memory access.** Implement a narrowly authenticated run-bound bridge through Hutch's existing memory operations, or explicitly retain an unsupported capability until that bridge is verified. Bind Bot/conversation/run/fence server-side; no model-selected authority, direct SQLite access or broad administrative endpoint. Test wrong scope, stale fence, cancellation, revoked share, memory disabled after construction, conflicting revisions and prompt-shaped hostile values. Keep proposals human-reviewed and facts out of the system prefix. [Starting contract](../../src/hutch/tools/memory.py), [scope enforcement](../../src/hutch/fact_memory.py#L82-L108).

4. **A4: Durable obligations plus bounded history retrieval.** Add ordinary-chat task anchors/checkpoints referencing canonical messages, with revision-CAS updates and explicit supersession. Expose scoped retrieval rather than unrestricted cross-Bot search. Separate pending work from receipt-backed outcomes; summaries never grant permissions or settle effects. Test corrections beyond 12 turns, repeated compaction, smaller/unknown windows, non-shrinking summaries and failed checkpoint writes. [Current bounds](../../src/hutch/store.py#L124-L143), [fitloop](../../src/hutch/runtime/fitloop.py), [receipt guidance](../../src/hutch/store.py#L8054-L8077).

5. **A5: Failure, delegation and retention regression gate.** Test crash-before/after event commit and mirror acknowledgement; stale worker projection; OpenCode partial/unreachable states; same-Bot children receiving no reference memory; named tasks receiving exactly selected snapshots; revocation stopping future retrieval without rewriting historical evidence; safe continuation refusing effects and changed policy. Keep permanent erasure as an explicitly designed follow-up, not renamed archive. [Existing fixtures](../../tests/test_store_events.py), [mirror](../../tests/test_transcript_mirror.py), [handoff](../../tests/test_conversations.py#L998-L1263), [memory](../../tests/test_fact_memory.py), [delegation](../../tests/test_delegation.py).

### Gaps

The new-session prompt must include this exact revision baseline, reread/status requirement, authority paths, chosen slice, acceptance IDs, explicit non-goals and test commands. Use existing environment and isolated fixtures; run focused tests then `uv run pytest --ignore=tests/e2e` when implementing, reporting unrun/blocked checks honestly. No paid inference, dependency installation, broader permissions, commits or publication are authorized by this audit. Product/web comparisons and live model-quality evidence belong to the other researchers; none are inferred here. [Repository check policy](../../AGENTS.md), [product constraints](../../PRODUCT.md).
