# Assistant applications: persistent chat and governed multi-bot memory

Research/access date: **2026-10-23**. Public, read-only inspection of official documentation and repository source; no installations, inference calls, or runtime/crash tests. All three requested applications were accessible; no substitute was needed. These are current development snapshots, not promises about older installed releases. Hutch documents below establish local constraints, not validation of the other products.

## 1. What survives restart, and what enters the next model request?

### Takeaway

Persistent chat means recovering canonical conversation records; it does not mean resending every retained message or reviving a dead executor. All three examples separate stored history from a bounded model-facing projection, although their storage and recovery machinery differ. [OpenClaw storage](https://docs.openclaw.ai/reference/session-management-compaction/store), [Open WebUI compaction](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/utils/context_compaction.py), [LibreChat checkpoints](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/compaction.ts#L49-L136).

### Cited Findings

- **OpenClaw now uses per-agent SQLite, not live JSONL as its primary transcript store.** Session rows map session keys to mutable metadata; append-only transcript events contain message/tool history, parent relationships, and compaction entries. Default location is `~/.openclaw/agents/<agentId>/agent/openclaw-agent.sqlite`; old `sessions.json` and transcript files are migration/archive artifacts. Startup refuses an unmigrated legacy store instead of silently presenting empty history. Each agent has separate history; DMs nevertheless share that agent's main session by default unless sender/channel isolation is configured. [Pinned storage specification](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/docs/reference/session-management-compaction/store.md), [session routing and migration](https://docs.openclaw.ai/sessions).

- **OpenClaw's retained history exceeds active context.** Compaction persists a summary and `firstKeptEntryId`; subsequent turns use that summary plus the retained suffix. The cut preserves assistant-call/tool-result pairing. Ordinary pruning is a distinct operation. Summary quality guards can eventually accept a visibly degraded summary, so persistence does not establish faithful recall. [Pinned compaction behavior](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/docs/reference/session-management-compaction/compaction.md#L20-L41), [quality limitations](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/docs/reference/session-management-compaction/compaction.md#L106-L130).

- **Open WebUI persists account-owned chats in its application database.** The default database is `DATA_DIR/webui.db`. `Chat` includes `user_id`, JSON history, and a current-message identifier. `insert_new_chat` commits the chat and dual-writes initial normalized messages; `upsert_message_to_chat_by_id_and_message_id` updates normalized messages and embedded history under a chat transaction. `get_chat_by_id_and_user_id` filters both identifiers. Thus retaining the database preserves committed histories across application restart; it is not merely browser storage. [Database default](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/env.py#L263-L271), [exact persistence/read methods](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/models/chats.py#L1326-L1363), [owner-filtered read](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/models/chats.py#L1892-L1908).

- **Open WebUI compaction creates a projection, not deletion of the source conversation.** `compact_messages_for_request` produces summary plus recent messages and persists `contextSummary` at eligible whole-turn boundaries. `_apply_latest_summary_checkpoint` reconstructs the suffix, including tool-loop checkpoint handling; `_find_compaction_boundary` preserves call/result batches. [Implementation](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/utils/context_compaction.py#L45-L152), [checkpoint readers](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/utils/context_compaction.py#L305-L377).

- **LibreChat separates MongoDB conversations/messages from transient streaming state.** Conversation schema records owner, message references, agent identity, and child lineage; `saveMessage` requires a user identity and writes through Mongoose. `isUsableSummaryPart` rejects failed/in-progress summaries and modern summaries without a completion boundary; `resolveCheckpointMessage` substitutes only a usable checkpoint. [Conversation schema](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/data-schemas/src/schema/convo.ts#L20-L100), [message persistence](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/data-schemas/src/methods/message.ts#L1133), [checkpoint functions](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/compaction.ts#L49-L136).

### Inferences

- For Hutch, preserve **conversation identity → attempts → committed messages/events → context manifests**. A restarted adapter should rebuild bounded role/content context from Hutch, rather than treating a provider's session identifier as the sole history. This extends the separation already specified in [ADR-0008](../../docs/adr/0008-memory-and-bounded-collaboration.md) and [ADR-0019](../../docs/adr/0019-cost-guardrails-context-continuity-and-routing.md).
- Persist a summary's covered message range, source revisions, route, and completion status. Incomplete summaries must never replace originals; changing runtime should select a new admissible projection, not erase the conversation. This recommendation follows the checkpoint mechanisms above.

### Gaps

- LibreChat's [resumable-streams overview](https://www.librechat.ai/docs/features/resumable_streams) broadly mentions server restarts, but its default backend is in-memory. The pinned [`InMemoryJobStore`](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/stream/implementations/InMemoryJobStore.ts#L148-L202) contains process-local maps. Do not generalize reconnect recovery to executor survival or durable retention of every uncommitted delta. No power-loss or backup-restoration guarantees were experimentally verified here.

## 2. How are durable memories scoped, reviewed, retrieved, and forgotten?

### Takeaway

The useful transferable distinction is **transcript evidence versus maintained memory**. Human-visible edit/delete controls do not imply approval before a model-written memory influences future turns. Hutch's immutable review-before-recall boundary is deliberately stronger than these examples' ordinary automatic-write paths. [Hutch memory contract](../../docs/adr/0008-memory-and-bounded-collaboration.md), [OpenClaw memory](https://docs.openclaw.ai/concepts/memory), [Open WebUI memory](https://docs.openwebui.com/features/chat-conversations/memory/), [LibreChat memory](https://www.librechat.ai/docs/features/memory).

### Cited Findings

- **OpenClaw: editable files plus derived retrieval.** `USER.md` holds profile directives, `MEMORY.md` durable facts/decisions, and dated `memory/*.md` working notes. Bootstrap loading is budgeted; daily notes are not all injected on every turn. Hybrid search combines vectors with lexical matching; `mergeHybridResults` explicitly combines vector/text scores while retaining path, snippet, and provenance fields. A default-on pre-compaction flush gives the model a silent opportunity to write memory, and default-on dreaming promotes qualifying material into `MEMORY.md`. `DREAMS.md` makes consolidation reviewable afterward; this is not mandatory human authorization of every promotion. [Official mechanism/defaults](https://docs.openclaw.ai/concepts/memory), [pinned hybrid implementation](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/extensions/memory-core/src/memory/hybrid.ts#L59-L139).

- **OpenClaw: lineage-based forgetting has explicit coverage limits.** `memory forget` removes tracked session-derived artifacts and records forgotten sessions to prevent re-ingestion; `--dry-run` previews, while omission deletes immediately. Original transcripts, arbitrary freeform edits, and outside copies are not universally erased. Consolidation preserves source origins, including across participating agents sharing a workspace. Ingestion exclusions do not stop tools directly editing memory files. [Pinned provenance/deletion contract](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/docs/concepts/memory-provenance.md#L12-L187).

- **Open WebUI: account-level typed snippets, semantic recall, and lexical browsing.** SQL memories have owner, `user/context` type, optional organizational path, content, metadata, and timestamps—not a per-bot scope column. Users can manually add/edit/delete. Native tools write directly; optional background review is off by default, but when enabled its model-generated operations call the same update route. `add_memory_context` queries using up to seven recent user messages/4,000 characters, combines profile, path-neighborhood, and relevant memories, then appends separately budgeted sections to system context. `search_memory_rows` supplies substring/path filtering, while `query_memory` uses embeddings and the user's vector collection. [Schema](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/models/memories.py#L15-L42), [injection/background-write functions](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/utils/memory.py#L290-L525), [retrieval](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/routers/memories.py#L328-L401), [controls/defaults](https://docs.openwebui.com/features/chat-conversations/memory/).

- **Open WebUI: source rows and vectors need coordinated lifecycle handling.** `delete_memory_by_id` deletes the owner-filtered database record and then its vector entry; these are separate awaited operations. Its reset/reindex routes distinguish authoritative records from derived retrieval. This is an implementation consideration, not evidence here of an observed leak. [Deletion and reindex source](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/routers/memories.py#L605-L623).

- **LibreChat: structured notepad, not semantic transcript memory.** Configured memory is key/value content injected into requests; the documentation explicitly says it does not embed/search the full chat archive. Manual create/edit/delete, valid-key restrictions, token limits, and per-chat personalization controls are available. Automatic extraction requires `memory.agent.enabled: true`; it analyzes a bounded recent window concurrently with the main request. Inline agent memory tools are independent and instructed to act only on explicit remember/update/forget requests. The source calls `setMemory` directly after validation; that instruction is not an immutable human review transaction. [Official memory guide](https://www.librechat.ai/docs/features/memory), [write/tool guard](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/memory.ts#L134-L374).

- **LibreChat: opt-in agent partitions are concrete authorization scopes.** Default memory is the user's shared personal pool; isolated agents use user-plus-agent partitions. The schema includes `userId`, `agentId`, key, and tenant identity. `getAgentMemoryPartitionAccess` requires current agent-use/view access, with a cleanup exception for deleted agents; `getMemoryAgentId` selects the configured partition. Request-scoped caching is partitioned and invalidatable. [Schema](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/data-schemas/src/schema/memory.ts), [authorization function](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/memory/authorization.ts#L49-L125), [partition/cache functions](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/memory.ts#L473-L588).

### Inferences

- Prefer LibreChat's explicit partition concept, OpenClaw's source lineage, and Open WebUI's inspectable inventory; keep Hutch's reviewed-revision gate and tool-reference framing. A display path or shared workspace is not a sharing grant. [Hutch review/scope rules](../../docs/adr/0008-memory-and-bounded-collaboration.md).
- Start with existing SQLite FTS5. Embeddings add provider/data-egress and index-reconciliation obligations without being necessary for restart persistence. Any later semantic index should contain derived identifiers and recheck current scope, review, revision, and tombstones before returning content. This is a recommendation, informed by the separate SQL/vector operations above.

### Gaps

- Recall quality and contradiction handling were not benchmarked. LibreChat's memory page contains an older-sounding “unconditionally” statement under Future Improvements alongside explicit opt-in instructions; report automatic extraction as configuration-dependent, not universally enabled. Neither file editability nor a “forget” control establishes deletion from provider logs, prior prompts, or backups. [LibreChat page](https://www.librechat.ai/docs/features/memory), [OpenClaw deletion limits](https://docs.openclaw.ai/concepts/memory-provenance).

## 3. How should handoffs and recovery shape Hutch's implementation scope?

### Takeaway

Separate **child execution**, **retained result**, **delivery obligation**, and **parent consumption**. Replaying a local delivery receipt can be idempotent without making a remote tool effect exactly once. Preserve Hutch's existing uncertain-effect reconciliation boundary. [OpenClaw announce](https://docs.openclaw.ai/tools/subagents/announce), [LibreChat wakeups](https://www.librechat.ai/docs/features/subagents#automatic-parent-continuation), [Hutch receipts](../../docs/adr/0003-durable-state-and-honest-outcomes.md).

### Cited Findings

- **OpenClaw:** ordinary children default to isolated context; explicit forks and thread-bound defaults differ. Completion carries task/session identity, execution-derived status, and bounded final output. Delivery is tracked separately; terminal execution alone does not prove receipt. Current restart recovery revalidates original operator authority and checks uncertain effects. `normalizeSubagentRunState` resets in-progress delivery without a durable queue ID to pending, illustrating why process-local flags cannot be recovery evidence. [Context modes](https://docs.openclaw.ai/subagents), [announce contract](https://docs.openclaw.ai/tools/subagents/announce), [recovery](https://docs.openclaw.ai/tools/subagents/operations), [normalization function](https://github.com/openclaw/openclaw/blob/42d41566c49cfccc727d5a0cd7aae1d5c4f428bf/src/agents/subagents/registry/subagent-delivery-state.ts#L127-L203).

- **Open WebUI:** `delegate` creates an internal child chat with parent/delegation IDs; it passes task/context plus configured chat-context messages and selected attachments. It also propagates tool/skill settings and potentially terminal identity. Foreground calls return bounded summary text; background completion persists an internal pending parent message and processes it when the parent is idle. Execution is launched through `asyncio.create_task`; task-ID storage does not serialize the live coroutine. [Exact delegate/result functions](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/utils/subagents.py#L279-L711), [task launch](https://github.com/open-webui/open-webui/blob/91ea4e3421d1d8069f13d4a463fcb5986d94ea60/backend/open_webui/tasks.py#L162-L183).

- **LibreChat:** isolated children do not inherit accumulated parent context/tool-search state. Detached children retain canonical MongoDB transcripts and lineage, but documentation explicitly says a live executor is not migrated after owner-process loss. Automatic completion targets the exact parent branch. `createSubagentCompletionWakeupHandler` registers a task-ID delivery before child provider work, orders it by parent conversation, and excludes ephemeral parents. [Subagent operation/limits](https://www.librechat.ai/docs/features/subagents), [complete registration function](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/subagentCompletionWakeup.ts#L825-L872).

### Inferences

**Prioritized adoption/rejection decisions — recommendations, not implemented changes:**

1. **P0: reliable canonical chat first.** Audit restart/readback and context reconstruction across supported runtimes. Keep SQLite authoritative, transcripts recoverable mirrors, and runtime sessions replaceable mappings. Preserve original messages and explicit interrupted/unknown outcomes. Acceptance: restart after an acknowledged turn retains identical IDs/order/content; switching runtime resumes the same bounded conversation without importing another bot's history. [Existing Hutch authority](../../docs/adr/0003-durable-state-and-honest-outcomes.md).

2. **P0: explicit sharing of reviewed revisions.** Extend existing fact grants only where a verified gap exists. Bind each share to owner, source scope, destination bot/task, exact revision, purpose, and optional expiry. Recheck current authorization on retrieval; a pending revision never inherits approval. Acceptance: bot B cannot search bot A's facts without a grant; altered content, revoked grants, and archived revisions are excluded before ranking/limits; memory-off blocks previously constructed runtime tools. [Existing scope/review contract](../../docs/adr/0008-memory-and-bounded-collaboration.md).

3. **P0: durable bounded handoff/result inbox.** Freeze task, selected reviewed facts/provenance, allowed artifact references, recipient, and parent attempt. Persist result plus delivery obligation atomically; use unique delivery/consumption keys and current fences. Acceptance: crash between result commit and parent acknowledgement produces one logical parent input after recovery; branch replacement, revocation, and late stale-worker replies cannot retarget it. Keep provider execution retries separate from delivery retries. [OpenClaw delivery evidence](https://docs.openclaw.ai/tools/subagents/announce), [LibreChat registration](https://github.com/LibreChat-AI/LibreChat/blob/94ae8a419839f8c99f5cfc15a650804ced8163c2/packages/api/src/agents/subagentCompletionWakeup.ts#L825-L872).

4. **P1: auditable continuity and forgetting.** Reuse Hutch's compaction manifests and reviewed-fact inventory. Distinguish archive/exclude-from-future-recall from permanent erasure; prevent excluded sources being resurrected by reindex/import. Acceptance: failed/nonshrinking summaries leave canonical evidence intact; archived facts stay absent after restart/reindex; source references remain inspectable. Permanent deletion needs its own retention scope. [Hutch compaction policy](../../docs/adr/0019-cost-guardrails-context-continuity-and-routing.md), [OpenClaw forgetting](https://docs.openclaw.ai/concepts/memory-provenance).

5. **Reject/defer:** automatic promotion of unreviewed model text into global/system memory; copying entire parent histories/workspaces; broad inherited credentials; automatic replay of uncertain external effects; embeddings as a prerequisite; general multi-agent orchestration in the first slice. OpenClaw explicitly documents additive shared-auth fallback and that workspace cwd is not a hard sandbox. Those are operational choices to avoid importing, not unsupported security allegations. [Authentication](https://docs.openclaw.ai/tools/subagents/nesting#authentication), [workspace boundary](https://docs.openclaw.ai/concepts/multi-agent), [Hutch runtime boundary](../../docs/adr/0007-external-runtimes.md).

**Suggested new-session implementation brief:**

> Read this note and current ADRs 0003, 0007, 0008, and 0019; verify implementation rather than assuming their status text is current. Map existing conversation persistence, reviewed-fact scopes, coordinator grants, and delivery queues before proposing migrations. Implement one missing P0 vertical slice at a time, preserving SQLite authority and runtime independence. Add meaningful restart, cross-scope denial, stale-revision, revocation, and duplicate-delivery evidence. Do not broaden tools/providers or replay uncertain effects. Report retained history separately from active context, retained results separately from delivered results, and executed checks separately from unsupported guarantees.

### Gaps

This research does not establish exactly-once external effects for any application, prove all crash windows safe, or validate Hutch's current code against its ADRs. Open WebUI's inspected task path alone does not establish complete restart resumption. Those require targeted implementation review and fault-injection evidence, not inference from a persisted transcript.
