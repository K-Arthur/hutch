## Failure research → named design responses (each gets a regression test)
Confirmed reports driving design (full evidence ledger goes in `docs/research/outputs-failures-2026-10-10.md` + evidence-ledger rows, in the repo's document-pipeline style):
1. **ComfyUI #6888** (2025-02, closed-dup): previews leak across workspaces because events are keyed by node ID only → every media/widget event carries backend-issued `job_id`/`blk_id` + `run_id`; per-run seq; cross-job isolation test.
2. **ComfyUI #9393** (open): WebSocket stalls after hours / on identical resubmits; UI waits forever → final truth lives on disk (content-addressed artifacts) and in SQLite; SSE resume + last-known snapshot with freshness; the socket is never the source of truth. Drop/reconnect/restart reconciliation test.
3. **open-webui #27399** (fixed 2026-07): artifact panel reopens on every streamed token and shows the stale artifact → inline compact blocks by default; expansion is user-owned state; closed stays closed; close-while-streaming lifecycle test.
4. **open-webui #14541** (fixed 2025-11): failed renderer drops the code block and the error → every typed block carries `{source, data, fallback}`; render failure shows source + error, never erases. Renderer-failure fallback test.
5. **open-webui #14823** (fixed 2025-06): displayed code garbles after execution → execution receipt stores exact submitted source + hash; display renders from the receipt; edits create new revisions; executed source is immutable. Post-exec fidelity test.
6. **open-webui #22267** (reopened 2026-03): reasoning-block HTML leaks into artifact previews → blocks originate **only** from the validated structured `tool_result` channel; message prose and reasoning are never parsed into widgets. Prose/reasoning inertness test.
7. Known class (ChatGPT-style silent environment expiry/state loss): explicit kernel lifecycle states (ready/busy/interrupting/lost/restart-required), stale-output markers after restart, visible state-loss warnings, persisted execution ledger.
(Web search for additional first-hand complaints was rate-limited during planning; the wave-1 research agent retries and extends the ledger.)

## Contracts first (slice S1 — everything depends on this)
- `src/hutch/outputblocks.py`: pydantic models for typed blocks — `text, code_receipt, dataset/table, chart, image/video/animation, flowchart, timeline, comparison, artifact_ref, status`. Block = `{id: blk_<hex16>, kind, revision, availability, provenance{run_id, job_id, tool}, payload}`; strict size/depth bounds; unknown kind/version → labeled fallback, never a crash. Model-facing text, user-facing presentation, and operational metadata stay separate fields.
- **`store.py _migrate_51` designed completely upfront** (lanes never touch store.py): `uploads` (per-conversation, sha256, mime, size caps), `media_jobs` (durable status machine, upstream ids, idempotency key, cost/consent fields), `workspace_sessions` (conversation-scoped kernel generation, env fingerprint). No media bytes in SQLite/events/context — content-addressed media store mirroring `documents/storage.py` (png/jpeg/webp/svg/webm/mp4/wav + previews).
- `steps.py`: validate `result.data["blocks"]` before persisting; bounded block refs on `tool_result` events.
