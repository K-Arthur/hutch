# hutch UI Redesign — Studio, Bots, Runs, Composer, Website

## Goal
Make the whole interface professional and coherent: Codex/Grok-inspired minimal tool calls in the Studio, shadcn-inspired (vanilla-CSS ports, improved) Bots/Runs/composer components, an aligned marketing site — all on one consolidated token system that passes WCAG AA, with ARIA/responsiveness throughout, progressive commits, updated docs, and visual-judge validation.

Research grounding: 18 verified complaints about agent dashboards (tool cards flooding transcripts — ChatGPT #1399987; GitHub Actions log crashes; Cursor surprise-bill backlash → live token feedback; Claude missing timestamps; color-only status coding; dead-end empty states; toast unreliability per Primer) + shadcn's documented gaps (weak focus-visible rings, DIY empty states, DIY table wiring, deprecated toast, a11y left to the dev). Docs/research/complaints.md pattern extended in docs/design-system.md.

## Design direction (brand kept, reduced + standardized)
Keep obsidian + emerald identity. One semantic token set shared by both surfaces: 6 surfaces, 3 text roles (all ≥4.5:1 — `--text-faint` #5a6b80 currently fails at 3.4:1, gets bumped/relegated to decorative), 3 border alphas (replacing ~8 ad-hoc ones), radius scale 4/8/12/16/full (no more stray 5px/6px/7px/11px), type scale 11/12/13/14/16/18 (fractional sizes eliminated), z-scale 40/50/100/110, motion 150ms ease-out with `prefers-reduced-motion` support, one focus-ring token (2px emerald — shadcn's #1 failure mode, made unmissable here). Violet/blue/amber/red stay as semantic status colors only. Emoji/icon chars stay banned (audit gate from commit 4803d1e enforces it).

## A. Foundations — dashboard style.css + index.html
- Rewrite `:root` with the token system above; replace every hardcoded color (`.tool-card #090e14`, input bgs, modal/toast bgs, inline `background:#0d1219` in app.js approval `<pre>`) with tokens.
- Style the currently-missing classes found by audit: `.empty-state` + real `.spinner`, `.page-title`/`.page-subtitle`, `.hint`, `.icon`/`.icon-lg`, `.icon-btn`, `.tool-verdict`.
- Fix dead selectors (`.topbar a.logo span` → `.brand`; `.section-head h2`), delete unused tokens (`--bg-subtle`, `--border-strong`, `--shadow-glow` — verify no use first).
- `transition: all` → specific properties (stops the nav crossfade artifact seen in baselines); focus-visible ring on every interactive element; reduced-motion media query.
- Skip-to-content link, `aria-current="page"` on active nav, topbar mobile wordmark fix (replaces broken `.logo` rule), `#topbar-new-bot` kept visible ≥600px, replaced by header CTA below that.

## B. Studio redesign (Codex/Grok-inspired) — the core
Tool calls become **single compact lines, not cards** (Codex CLI pattern):
- Each tool event = one ~28px line: verdict glyph (spinner while running, check/x when done) + tool name (mono, violet) + one-line truncated arg summary (dim) + duration/timestamp right-aligned. Click/Enter/Space toggles an inline expand with full args + output (aria-expanded, real `<button>`); expansion remembered per run in localStorage (the "collapse state resets" complaint).
- `tool_call` + matching `tool_result` merge into ONE line (running spinner → final verdict) instead of two stacked cards — halves the vertical footprint.
- ≥4 consecutive tool lines group under a collapsible "Ran N tools" summary row; long output capped ~12 lines with "Show more".
- Errors stay red-tinted lines; the run-level error becomes an alert row, not a card.
Feed: user prompt = quiet right-aligned tint (no border, no bubble shadow); agent messages plain text with small role+time label (timestamps on everything — the Claude complaint). Approval gate stays prominent amber (safety hierarchy) but tightened: live TTL countdown (static text today — real timer with `aria-live` off), detail `<pre>` capped + expandable, Approve/Deny + always-allow row. Add `role="alert"` so pending approvals announce.
Composer: shadcn-input-inspired field (token bg, border, strong focus ring), Send with icon, Enter/Shift+Enter documented in placeholder, **Up-arrow recalls last prompt** (ChatGPT Enter-fight complaint), token budget as mini progress meter with amber/red states near cap (Cursor surprise-bill complaint), quick-prompt chips restyled as ghost chips.
Behavior fixes while in there: polling interval leak (stacking `setInterval`), dead `lastEventId` (use `after` cursor properly), `renderRunDetail` fire-and-forget.

## C. Bots + Runs (shadcn-inspired, functionally better)
Bots: cleaner card anatomy — header (name + status glyph+word badge), description, meta chips row, 2×2 facts grid, actions row; ONE primary per card (Run); Pause/Studio as ghost; page-header "New Bot" removed (topbar keeps the global access point — brief's duplication rule). Distinct empty state with "Create your first bot" CTA.
Runs: **wire the currently dead filter buttons and search box** (P0: they render but have zero listeners — controls disconnected from behavior); filters reflect in hash (`#/runs?status=failed&q=…`) so state is shareable; sticky table header; status = glyph+word chip; right-aligned mono token/steps columns; row title attrs with absolute timestamps; "Load more" pagination (API already takes limit); sortable ID/time columns skipped unless trivial; distinct empty state. Approvals queue: same card language as studio approval gates (consistent safety surface), live TTL, distinct empty state.
All `confirm()` dialogs replaced by the existing modal system (destructive actions red-confirmed); toasts get dismiss buttons + errors persist until dismissed (Primer/sonner complaints), `aria-live` regions set politely.
