# Settings-layout structural fix for Hutch (Apps & AI + assistant settings)

Work happens directly on `main` (this repo's default; the pasted prompt's "master" is generic boilerplate). No branch, no push. All commits local, staged file-by-file (never `git add .`).

## Diagnosis (evidence-backed)

**Symptom:** peer controls at the same level don't share alignment axes; nested disclosures indent by unrelated amounts; some corners render square and some surfaces transparent.

**Semantic problem:** visually-implied hierarchy contradicts actual hierarchy — most notably Outlook event-creation (a *separate* connection with its own sign-in/accounts) is nested inside the read-access disclosure, reading as its child. Five disclosure summaries (assistant-more-settings 42px/68px, assistant-usage-details 30px/64px, provider-advanced flex/44px, connection-management flex/56px with +/− glyph, device-manager 44px) share no icon-slot, min-height, or padding axis. Inside "More account settings", three sibling heading treatments coexist (`.bot-head`, `.custom-service-heading h3`, `.model-capability-card .bot-head`).

**Technical causes (root-cause matrix):**
- **C/M/N (tokens, missing primitive, historical duplication):** no shared settings-row/disclosure primitive; each surface hand-rolls geometry.
- **Real rendering defect:** `--r-control` (18 uses), `--surface` (12), `--r-md` (2), `--bg-subtle` (6) are referenced in the SPA's CSS but defined nowhere → invalid-at-computed-value-time → initial values (square corners, transparent backgrounds) across `.provider-choice`, `.provider-discovery-note`, `.setup-choice`, `.workspace-task-card`, `.run-card`, `.google-oauth-setup`, etc. Violates DESIGN.md's Scale Rule.
- **E/G (hidden geometry, intrinsic sizing):** magic offsets — `.conn-provider-heading { align-items:center !important }`, `margin-right:2px`, `margin-top:3px`, inline `style="margin-left:auto" / "width:100%;margin:8px 0" / "margin-top:12px"` in app.js card markup; control-height drift (32/36/44/46px; the new key input/reveal pair is a 46px one-off vs the documented 44px touch target).
- **Markup bug:** doubled `</details></details>` in the Outlook sections (app.js ~6498/6536).

**Scope:** Apps & AI screen (`renderConnections`, app.js 6078–7580), assistant settings disclosures, provider connect modal; token repair is repo-wide but mechanical.

## Research findings that shape the fix (sources recorded for the final report)

Failures to avoid: macOS Ventura System Settings (misalignment reads as "unpolished"; mixed switch/checkbox vocabulary; low-density scroll waste), Windows 11 dual-settings split, VS Code one-page overload, GOV.UK warning not to hide majority-needed info behind disclosure, NN/g: **max 2 disclosure levels** (Ventura-style burial generates years of complaints). API-key flows: Continue/Open WebUI/Jan/Cursor failures → validate on save with stage-specific errors, never duplicate on re-connect, show/hide + get-key link (the in-flight feature already does most of this). WCAG 2.2 AA 2.5.8: ≥24px targets; keep 44px. MDN: undefined `var()` computes to initial (why the token bug is silent) → guard with a lint-style test (stylelint `no-unknown-custom-properties` pattern). Subgrid is Baseline-widely-available but **not needed** here (columns are per-card, not cross-card) — a shared row template is the right-size primitive; documented as a rejected alternative.
