  1. 01

    Say what you need

    Start in chat. If you turn a request into a dedicated assistant, Hutch carries your words into setup, suggests an editable name, and lets you create it without describing the work again.

    Customize the assistant when you want to

    New can start from the latest request in the current chat. Hutch suggests an editable teammate name, clear work role and stable local address without an extra model request. With a saved workspace or source-chat model route, setup stays on one screen and creating the assistant starts no run. Without a configured route, Hutch asks you to choose one.

    Customize opens model, workspace, tools, memory, schedule and limit settings. Only the selected request and earlier user messages you choose become saved background; later messages, assistant replies and other chats stay excluded. New assistants start in a managed workspace with no tools or schedule and ask before actions that require approval.

    Experimental (built-in coordinator only): request a tool-free purpose rewrite from the exact source; each request returns one response. Select earlier user messages if useful. Edit and apply the draft yourself; it lists unknowns rather than guessing. Drafting creates no assistant or permission changes. Normal route and fallback limits still apply; hosted providers may retain the text, and live quality is unverified.

  2. 02

    Choose what happens next

    If Hutch needs your preference, it can offer clear choices right in chat. Your reply guides the conversation; it never approves an action. Review an approval in the chat or Needs you, then allow once or say no.

    How assistant handoffs and checkpoints work

    Experimental coordinator handoff: only assistants on the owner-approved roster can receive a new task. Manage that list in coordinator settings, then review the specialist's saved settings, refine the goal and optional deliverable or constraints, and confirm. The coordinator chat keeps the original request, task, response and content-free progress timeline together; changing the roster never stops existing work.

    Continue only from a safe checkpoint: the failed or stopped built-in attempt has no recorded action or child work, and no later specialist work, pending question or uncertain effect; the coordinator chat and specialist settings must remain active and unchanged. Hutch starts a fresh run from the reviewed brief, constraints and committed response; it never resumes the old worker or replays actions. External runtimes stay blocked, and a new model call may use more quota.

    Attach only the exact specialist reply you choose, as untrusted text; other chat history, files and permissions stay separate. You may also select up to eight current, approved coordinator facts for that task alone. They are not specialist memory; providers may retain submitted copies. The specialist's own memory and workspace may apply. Live provider execution is unverified.

  3. 03

    Come back to the result

    Find the answer and what Hutch did in the same conversation. Keep useful work nearby, share only the background you choose, and return to repeat requests when you need them.

    More about history, files, and memory

    Inspect the final status, tool results, ordered transcript and reported usage. Uncertain effects remain visible for reconciliation. Keep memory private by default. If another assistant needs a fact, share the reviewed snapshot with that named assistant. Either side can revoke; the share adds no tools, account access or workspace context.

    For repeat work, save a reviewed request in Hutch’s local library and search for it from another chat. Choosing one fills a draft only; you still review and send it yourself.

    Documents Hutch creates — PDF, DOCX, XLSX, PPTX, CSV, JSON, Markdown or a ZIP bundle — are stored on your machine as versioned files with recorded SHA-256 hashes. Downloads come straight from that local store, so a file does not expire with the chat that made it, and each preview says whether it is the extracted content or an approximate render.

Question: “What is a checksum for?”

Brief

A checksum is a short value that helps detect whether data changed or was corrupted.

Detailed

A checksum is calculated from a block of data. Recalculating it later helps catch accidental changes or corruption. Ordinary checksums can check integrity, but they do not prove who created the data or protect it from deliberate tampering.

Explore model, privacy, and computer details

Inference

Hutch supports configured OpenAI, Anthropic, OpenRouter, other OpenAI-compatible and Ollama routes. OpenRouter’s searchable model catalog is loaded when you open model choice; model availability and listed prices can change. In Studio, review the selected route, draft context and current spend policy before sending; choose an exact route for the next message, assign manual routes to task roles, or select Save as Bot default for future chats and scheduled runs. Strict OpenRouter USD ceilings require fresh endpoint pricing and block when Hutch cannot establish a safe estimate. Estimates are not provider billing guarantees; live inference and model-quality checks have not been performed for this preview.

Execution

Runs are supervised on Linux. Bubblewrap isolation is a Linux namespace sandbox, not a virtual machine, and must be enabled by the operator. Migrated bots may remain unsandboxed.

State

SQLite, transcripts and file-share records stay in ~/.local/state/hutch. Workspaces start fresh per run; choose a managed folder for one bot or a validated user folder. Chat Files lists verified downloads. The owner can add a revocable reference to another selected chat; bytes stay with the source run, outside the target workspace and model context. Shell-created files are not attached automatically. Managed folders survive bot deletion and sit outside database snapshots; back up those files separately.

Scheduling

One elected local supervisor runs schedules. The dashboard shows each next run in its own time zone and the task's catch-up policy. One workspace-wide pause stops new scheduled admissions while queued or running work continues; when resumed, missed windows are coalesced or skipped according to each task's policy. The host must be awake and the service running; sleep and disconnection are visible limits.

Supervised computer use

See captured frames, stop a task or take explicit step control of its owned browser or private Linux desktop. Paired devices need separate viewing and input permissions over your existing private HTTPS connection. Native apps have workspace-only user files and no network. Human text and frames stay out of the AI’s history.

Plans & keys

OpenCode Go uses its issued API key, copied into Hutch after you sign in there. Sign in with ChatGPT is an opt-in local preview; eligibility for Hutch is unconfirmed and scheduled use requires a separate permission for each Bot and account.

The honest limits

5 boundaries
  • Isolation has a boundary. Linux bubblewrap mode uses namespaces and resource limits; it is not a VM. It must be enabled, and migrated bots remain unsandboxed until an operator changes the setting.
  • Humans still review consequential actions. Prompt injection can produce harmful requests; approvals and denials reduce risk but cannot make an allowed action safe.
  • Usage amounts are estimates. Warnings, approval pauses and estimated admission ceilings are separate controls. Hutch reserves before metered hosted calls; provider tokenization and billing remain authoritative.
  • OpenCode coding tasks are experimental. A reviewed task can open the user's OpenCode CLI in a pinned worktree. Run hutch code login once to connect a provider in a private Hutch-managed profile; this does not copy the regular OpenCode profile. Provider usage and approved shell commands remain outside Hutch's budgets and sandbox. OpenCode and Pi are unavailable as Hutch-managed Bot runtimes.
  • Computer control needs explicit permission. Experimental step control uses bounded still frames, clicks, text and keys in an owned browser or disposable KWin Wayland desktop. It pauses when supervision is lost and requires a fresh frame before input. Conventional browser secret fields are masked in the human preview; detection is best effort. Viewport emulation and native input were tested locally; physical phones, live remote networks and arbitrary GUI grounding remain unverified. Hutch does not solve CAPTCHA or bypass challenges.
  • Delegation has a narrow boundary. The optional child-task tool requires a supervised Strict Offline Linux run and a fresh approval for every request. Children receive only the task text, run one at a time under the default two-run limit, and do not copy files into the parent workspace.

What usually stops people

The questions people actually ask before trusting an agent with their machine.

Do I need an API key, a credit card, or a GPU?

Hutch does not include hosted inference. Connect a compatible hosted provider or use a local model service that you already run; available models vary, and live paid-provider checks have not been performed for this preview.

Can I choose how Hutch answers?

Yes. Set voice (Direct, Warm, or Dry Wit), answer depth (Auto, Brief, Standard, or Detailed), and humor (Off, Subtle, or Playful) independently. Humor defaults to off. The fixed examples above use written sample text and make no model request; changing a setting also makes no request. If you choose the separate live preview, Hutch shows a local one-response estimate first and uses a fictional prompt without your conversation, tools, skills, or workspace. Style guides wording and cannot change permissions, approvals, evidence, spending, requested formats, or recipients. Provider adherence and live answer quality remain unverified.

Can Hutch look at an image I attach?

No. Hutch chat is text-only today: it does not attach or send image files. The Vision focus option only tunes context and model residency; it does not enable image input. Describe the image in text instead.

What happens to files Hutch makes for me?

They are kept on your machine in Hutch’s own document store, not in a temporary session that expires. Every download is checked against its recorded size and SHA-256 before it is served, revisions create new versions while older versions stay downloadable, and previews are labelled as extracted content or approximate renders rather than pretending to be the exact file.

What actually leaves my machine?

Hutch stores its control state locally. A hosted model receives the prompt and context Hutch sends to it; network tools connect to their own destinations. A local model can still use online tools. Review the selected connection and tools before running a task.

Can I use different models for different kinds of work?

Yes. Assign exact provider/model routes to task roles such as summarization, code analysis or verification, then choose a role for one chat message. Hutch checks the selected route's setup, context fit and spending policy before it starts. Fallbacks handle unavailable routes; escalation handles repeated quality failures. Automatic classification is not enabled, and a role name is not a model-quality guarantee.

Will Hutch summarize my chat automatically?

Hosted summaries ask first by default and have their own estimate and budget reservation. You can explicitly opt into automatic summaries or turn them off. Hutch keeps the original conversation and stops if a summary does not reduce the context enough.

What happens when my laptop sleeps on a schedule?

Nothing runs while the machine is off. With the local supervisor running again, configured schedules detect missed windows and either coalesce them into one catch-up run or record a skip, according to the bot’s policy.

How do Suggest and Auto work for workflows?

New assistants start in Suggest. The setting is stored per conversation, and changing it never starts work. A chat route card and Auto start require selector qualification for the exact active model profile; the two local profiles tested did not qualify. Auto can start only a matching activated saved method within explicit limits. It does not create a new plan, and consequential actions still need separate approval.

Can a local model design or choose a workflow?

Author and selector authority depends on evidence for the exact model and execution settings. Neither of the two Qwen3 profiles tested qualified for authoring or selection. Hutch does not silently switch to another provider. You can still start a saved workflow when its required model roles are qualified for your route.

What happens if I stop a workflow or Hutch restarts?

A pause request does not cancel active work: the current node and owned child work settle before the next step is held. If the run is already parked, it pauses immediately. Pending questions remain answerable, and no downstream step starts until you resume it from the same chat. Stop cancels work owned by that workflow and keeps its status visible until cleanup is verified. After a restart, settled steps and completed effect receipts are reused; if an external effect is uncertain, Hutch holds retry for reconciliation. Some recovery paths remain under evaluation in this private preview.

What is the difference between a workflow and a routine?

A workflow describes the steps to do; a routine decides when work runs. Saving or importing still starts nothing. After you activate a saved workflow, you can link it to an existing routine; Hutch pins the exact revision and checks its inputs. The routine stays off until you enable it separately. Run now starts that pinned workflow once without moving the next scheduled occurrence. The local supervisor and host must be running when the routine is due.

Can I hand coding work to OpenCode?

An experimental Linux handoff can turn a completed Hutch answer into a reviewed coding task. Run hutch code login once to connect a provider in Hutch's private profile; your regular OpenCode sign-in stays separate. Review the task, then launch it in a terminal. Hutch creates a separate worktree from the selected Git commit, leaving your original project folder untouched. OpenCode controls the model, usage, and command approvals. Approved commands run with your Linux account's permissions, outside Hutch's budget and sandbox. This is a CLI handoff, not a managed Hutch assistant.

Can I run it on my ChatGPT or Claude subscription?

OpenCode Go connects through its provider API key: sign in with OpenCode, copy the key, and add it to Hutch. A separate experimental coding handoff uses OpenCode's interactive provider sign-in inside a private profile managed by Hutch; it does not import your regular OpenCode profile. Its model use remains outside Hutch's budgets, and its command approvals are outside Hutch's sandbox. Sign in with ChatGPT is an opt-in local-app preview; eligibility for Hutch is unconfirmed and its Responses API does not enforce Hutch's output-token allowance. Scheduled or coordinator-assigned work needs your express permission for each Bot and connected account; the permission follows that Bot's current provider routes and can be revoked. Hutch never reuses consumer-app cookies or sessions, and no plan is silently upgraded or selected as a fallback.

What does a runaway bot cost me?

Set a warning, an approval pause, and an estimated admission ceiling independently. For OpenRouter, a strict USD ceiling requires fresh endpoint pricing; Hutch blocks if it cannot quote an eligible route. Estimates can differ from the provider’s invoice and are not an external spending guarantee, so use provider-side billing limits as well. Uncertain charges remain held until reconciled.

Can I review cost and context before sending?

Studio can estimate the selected route, your current draft, the bounded recent conversation context and the applicable spend policy before you send. It is a preview: context can change before admission, and providers control final tokenization and billing.

Is it safe to let an agent touch my files?

Bubblewrap isolation is available only on Linux and must be enabled; it is not a virtual machine. Approval policy and transcripts provide operator control but do not guarantee safe decisions. Legacy bots may still have isolation disabled. Read the support boundaries above before use.
