Architecture · Bento Grid

Engineered for absolute local reliability

The agent prompt loop is simple. hutch is the hardened operational plumbing around it: sandboxing, scheduling, approvals, budgets, and append-only audits.

SECURITY & SANDBOX

Workspace Jail & Policy Engine

No ambient authority. Every bot operates strictly within its designated disk perimeter.

  • Path containment: Tools cannot resolve paths outside the run workspace.
  • Environment scrub: Shell commands run with synthetic HOME and sanitized env vars.
  • Compound-command aware: Parses &&, ||, ;, | to prevent chained injection bypasses.
  • Public-only egress: Web fetches blocked from localhost, internal subnets, and cloud metadata IPs.
DETERMINISTIC SCHEDULING

Cron that Survives Real Life

Engineered for real computers that sleep, reboot, travel across timezones, and change DST.

  • Sleep catch-up: Detects missed schedule intervals and coalesces them cleanly into one run.
  • DST & Timezone safe: Explicit IANA timezone handling eliminates duplicate fires and missed hours.
  • Single-instance locks: Per-bot mutexes guarantee scheduled tasks never clobber each other.
  • Staleness monitors: Flags bots whose last success timestamp exceeds their schedule expectation.
HUMAN-IN-THE-LOOP

Kind Approvals · Fail-Closed

Supervision that respects developer time without compromising safety.

  • Fail-closed TTL: Unanswered approval requests expire as denied after 10 minutes.
  • Sticky allows: Tick "always allow" once per bot; revoke anytime in the Studio inspector.
  • Browser CAPTCHA pauses: Playwright browser pauses for a human at MFA/CAPTCHA walls instead of guessing.
  • Persistent logins: Chromium profiles persist per bot so repetitive logins are eliminated.
LOCAL SOVEREIGNTY

Transcripts, Budgets & Pluggable Runtimes

Everything lives in one directory on your disk. Complete control, zero lock-in.

  • Append-only transcripts: Every prompt, tool call, output, and token count stored in SQLite + JSONL.
  • Hard spending caps: Max steps, execution timeout, and daily token quotas per bot.
  • Model agnostic: Connect to Ollama, llama.cpp, LM Studio, OpenAI, or run offline on our mock runtime.
  • Pluggable harnesses: Default ~300 line auditable loop, or delegate bots to Pi / OpenCode.

Quickstart

Two minutes to your first supervised bot

The included mock model runs the entire platform offline without API keys or accounts. Switch to Ollama or OpenAI whenever you are ready. 

# 1. install from a clone
$ git clone https://github.com/K-Arthur/hutch && cd hutch
$ pip install -e .

# 2. state directory + 3 starter bots (mock model, no API key)
$ hutch init

# 3. dashboard + approvals
$ hutch serve            http://127.0.0.1:8787

# 4. point a bot at a real model whenever you choose
$ hutch bot update research-briefing --model ollama/llama3.2

# 5. headless daemon: cron, catch-up, approval expiry
$ hutch daemon

Frequently Asked Questions

Fair questions with honest answers

Do I need an API key, credit card, or GPU?

No. hutch includes a built-in deterministic mock runtime that runs the full tool and approval pipeline completely offline for free. When you want real intelligence, connect any local model (Ollama, llama.cpp on CPU or GPU) or any OpenAI-compatible endpoint with an API key.

Does hutch phone home or send telemetry?

No. Zero telemetry, zero phone-home, zero accounts, and zero analytics. Everything lives inside ~/.local/state/hutch on your disk in SQLite and JSONL files you can inspect, back up, or delete.

How does hutch differ from OpenClaw?

OpenClaw provided a lightweight local agent but shipped with zero out-of-the-box guardrails, ambient shell authority, and flat markdown memory that suffered desync. hutch provides isolated workspace path jails, sticky human-in-the-loop approvals, structured SQLite memory you can inspect, and hard token budget caps.

What happens if my laptop goes to sleep during a scheduled run?

hutch tracks schedule intervals in the bot's IANA timezone. When your machine wakes up, the scheduler detects missed windows and triggers a single catch-up run tagged with +N missed windows, preventing silent run loss and avoiding duplicate execution stampedes.

What happens when a browser bot hits a CAPTCHA or MFA wall?

hutch emits a pause-to-human event and waits for you. Bots never hallucinate clicks on verification walls or try to solve CAPTCHAs. Because Chromium profiles persist per bot, logins survive between runs.
