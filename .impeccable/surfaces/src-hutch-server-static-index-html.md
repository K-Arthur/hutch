# Surface brief — Hutch personal assistant (SPA at `/`)

Mode: **Operate**. Visitor: someone using a personal assistant, with specialist helpers
and optional technical controls. Targets: desktop (1280–1920), tablet (768–1024), and
phone (320–430, keyboard open). Surfaces: conversations, assistant list and settings,
approvals, apps and models, activity, schedules, history, and first-run welcome.

## Direction contract

THESIS: a helpful, familiar assistant app with recognizable service marks and a
conversation at its center. Technical configuration stays available, but the first
view shows what Hutch can help with and the next step in language ordinary people use.
Important permissions and real run state stay clear wherever they affect a decision.

OWN-WORLD: emerald lineage for brand + primary action with near-black ink; azure
interaction only; amber only for person-needed-now; rose for failure. One rounded
scale (8/12/18/22/100) after an explicit user override of the earlier square
language. System sans for language at reading sizes; mono strictly for measured
values. Elevation by offset+blur shadow + hairline, never glow.

STORY: a person opens a chat, describes what they need once, optionally creates a
specialist from that request, connects a familiar app or AI model, and reviews each
important action before it happens. The same chat shows what is waiting, finished,
or needs the person's help.

FIRST VIEWPORT: a compact sidebar with Chats, Needs you, a collapsed More menu, and
an assistant list with one options menu per assistant; a 56px context header with
assistant identity and conversation actions; and a comfortable conversation column
with readable messages and a familiar composer. Status appears only when there is
useful information. The first-run view welcomes the person with a simple 2D Hutch
character, a plain-language invitation, and clear choices for creating an assistant
or choosing an AI model.

SETTINGS: the first view shows the assistant's editable name and short role. Standing
directions and technical customization stay inside one optional, icon-labeled
disclosure; keep it open while saving related changes.

SIGNATURE: simple, expressive 2D assistant identities in conversations, empty states,
and the roster; familiar vector service icons in Apps & models; restrained emerald
actions; and readable, human copy. Each assistant may use a distinct head silhouette
and name-stable color. Its balanced eye pair follows the face area of that silhouette
and stays fully inside it. Status remains a separate, labeled indicator. Marketing
can use the original, more detailed 3D character art, with matching colors and tone.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish
review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.
