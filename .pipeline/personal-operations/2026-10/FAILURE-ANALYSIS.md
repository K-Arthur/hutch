# FAILURE-ANALYSIS: what breaks in personal operations, family workflows, coding orchestration and automation

Dated: 2026-10-31. Access date for all sources: 2026-10-31. Every row states its basis: VERIFIED
(primary doc/issue/advisory/paper), OBSERVED (page fetched), COMPLAINT (user report), HYPOTHESIS
(our inference). Complaints are not incidence; issue counts are project-scale artefacts. The
countermeasure column is what the evidence implies, not a claim that any vendor implemented it.

## 2. Cross-cutting countermeasure model

The rows above reduce to a small set of primitives. This is the part Hutch can implement once and
reuse across personal, shared and coding work. Where a row cites a bare issue number (for example
#46755), its metadata, date and tag are in the source list at the end of this file.

| Primitive | Prevents | Minimum implementation | Evidence basis |
|---|---|---|---|
| Authority record | Unbounded or stale permission; agents widening their own scope | Standing grant with scope, risk class, expiry; revalidated per run | S9, S14, #8776, #45740, CVE-2026-24764 |
| Idempotency key | Duplicate orders, messages, calendar events, reminders | Stable key per side effect; dedupe store; never retry an action that may have landed | S4, S5, S2 |
| Reconciliation | "Unknown" outcomes silently treated as success or failure | Provider-state check after ambiguous send; owner-visible Unknown with next step | S4, S6 |
| Approval binding | Approving one action and executing another; rubber-stamped approvals | Hash of action + parameters + target in the approval row; execution refuses drift | S14, S20; Hutch ARCHITECTURE already specifies approval CAS |
| Run receipt | Claims without evidence; unreviewable automation | Append-only record of command/tool, inputs hash, result, artifacts, timestamps, actor | S6, S7, S23, S18 |
| Scoped visibility | Cross-user and cross-space leakage; household data bleeding into every bot view | Per-person/per-space record scope; grants evaluated at read and at tool call | S15, S16 |
| Truthful completion | False completion, "done" without file/test evidence | reported / unverified / verified kinds; artifact existence and test checks | S18, #46755, #44925 |
| Budgets and caps | Token blowups, recursive fan-out, runaway loops | Per-run/agent/day spend cap, depth cap, concurrency cap, kill switch | #42475, #72861, S3, S16 |
| Catch-up policy | Missed runs replayed twice or silently dropped | Explicit policy per schedule kind: catch-up, skip, coalesce; visible missed count | S6, S5, S7 |
| Timezone contract | DST and wrong-zone reminders | IANA zone required; UTC instant stored with zone; reject nonexistent local times | S5, S7, #10841 |
| Loop guard | Infinite agent conversations, thousands of messages | Pair/conversation sliding window, max turns, outbound dedupe | S1, #1649, S2 |
| Isolation | Parallel agents corrupting one repo or overwriting files | One isolated workspace/worktree per task; serialized integration; preserve on failure | #55724, S3 |
| Backup and rollback | Upgrade or destructive action without recovery | Pre-change snapshot; additive migrations; rollback path in the receipt | S22, #153257 |
| Review gate | Unreviewed agent code shipping | Diff + test evidence required before merge; no self-merge for agent work | S16, S19 |

## 3. How to read the occurrence evidence

- Primary issues are the strongest evidence here: they are dated, versioned, reproducible reports,
  and several are still open (#44925, #42475, #153257, #79330). They still do not prove prevalence.
- The OpenChamber study is the only measured complaint corpus in this research. It is
  competitor-authored, Reddit-derived, and documents its own instrument bias; use its ranks and
  relative multiples, not its absolute percentages, when talking to users.
- The X/HN evidence is anecdotal and self-selected. The showcase loop quote (S2) is valuable
  precisely because it appears on the vendor's own marketing page.
- Several failure classes - calendar conflicts (F5), family recipient consent, mobile UX depth
  (F16) - are supported mainly by design evidence and user complaint summaries. They are marked
  HYPOTHESIS where the specific incidence is unknown; the countermeasure is still justified by the
  asymmetry of harm.

## 4. Evidence gaps to close in-product

- No public data on duplicate-action rates for agent platforms; instrument dedupe counts locally.
- No public data on how many scheduled runs are missed per month in self-hosted agents; the fix
  is a first-class missed-run metric, not a better model.
- No verified pricing for Google Workspace AI, Microsoft 365 Copilot, Codex or Claude Code in this
  pass; do not quote prices for them from this directory.
- Calendar conflict evidence is pattern-level, not incidence-level; a Hutch implementation should
  log every proposed calendar change and its reconciliation outcome to build that dataset.
- The OpenClaw issues cited are a sample chosen for class coverage, not a survey; the repository
  has 62,196 issues total (search API, 2026-10-31), which makes total counts meaningless.
