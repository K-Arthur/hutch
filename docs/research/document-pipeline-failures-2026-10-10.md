# Research: document/file generation failures across AI apps and libraries (2026-10-10)

This file is the traceability backbone of the document pipeline feature: each design decision and
regression test cites a *reported* failure class. It follows the rules of
[complaints.md](complaints.md): a single report is an anecdote, not a prevalence claim; "closed"
upstream issues are test cases, not current defects; nothing here was tested against the live
commercial products. Library versions and upstream issue statuses below were re-read first-hand on
**2026-10-10** (PyPI JSON API and the linked issue pages); rows sourced only from search summaries
are marked *(search-derived)*. The machine-readable rows live in
[`docs/realignment/evidence-ledger.md`](../realignment/evidence-ledger.md) section E.

Scope question: *hutch generates documents locally, stores them locally, and serves downloads
through its own authenticated loopback server — so which failure classes that users actually
complain about elsewhere can hutch structurally avoid, and which must it defend against with its
own gates?*

---

## 2. Office/XML generation: corrupt files and lying values

| Reported failure | Evidence | Mechanism | hutch answer |
|---|---|---|---|
| **"Excel found unreadable content" repair prompts.** A newline in a cell serialized as `_x000A_` made workbooks unopenable (fixed upstream in a day, but the class persists across libraries); list data validation rendered a whole workbook unopenable; `fromArray()` null handling corrupted files; a code-interpreter DOCX with an image triggered the Word repair dialog. | [PhpSpreadsheet#4619](https://github.com/PHPOffice/PhpSpreadsheet/issues/4619) (2025-08-29, fixed 2025-09-01), [#2368](https://github.com/PHPOffice/PhpSpreadsheet/issues/2368) (2021-11-03), [#1639](https://github.com/PHPOffice/PhpSpreadsheet/issues/1639) (2020-09-04), [community.openai.com/t/702414](https://community.openai.com/t/microsoft-word-unable-to-display-images-added-to-it-via-open-ai-assistant/702414) (2024-03-30) | OOXML schema violations: control characters, malformed parts, dropped relationships. | A validation gate runs before a version is promoted: zip/XML integrity of every part, independent reopen with a second library (openpyxl / python-docx / pypdf), and bounded page/cell counts. `failed` validation is never downloadable as ready. Regression: `tests/test_docgen_validate.py`. |
| **Formulas display 0 / stale until a manual recalc.** Mac Preview shows `0.00` because no cached value exists; the library writes a dummy `<v>0</v>`; array formulas show `#NAME` until the cell is edited. | [XlsxWriter#864](https://github.com/jmcnamara/XlsxWriter/issues/864) (2022-03-10), [#877](https://github.com/jmcnamara/XlsxWriter/issues/877) (2022-06-10), [#926](https://github.com/jmcnamara/XlsxWriter/issues/926) | XLSX stores last-computed values; Python writers do not compute, and many viewers do not recalculate on open. | Formulas are written with explicit cached results (`write_formula(..., value=)`), auto calc mode is set, and the validator recomputes representative results from the source data and compares them to the cached values. Regression: `tests/test_docgen_xlsx.py::test_formula_cached_values_match_recompute`. |
| **Text edits destroy formatting.** Assigning `paragraph.text`/`cell.text` replaces runs and wipes run-level formatting; Word fragments text across RSID runs so whole-paragraph replacement is inherently lossy. Closed "completed" with guidance only — never fixed in code. | [python-docx#1251](https://github.com/python-openxml/python-docx/issues/1251) (re-read 2026-10-10: closed without code change; see also #415, #1038) | Run-level structure discarded by the naive edit path. | Revisions never use `.text` assignment: scoped edits operate at run/XML level on documents hutch generated (whose structure it knows); arbitrary imported files are disclosed as reconstruction, never silently rewritten. Regression: `tests/test_docgen_docx.py::test_revision_preserves_unrelated_formatting`. |
| **Theme/style indirection silently ignored.** Setting a heading font via styles has no effect because of theme references; custom bullet styles are written but not rendered; `KeyError: 'Table Grid'` on LibreOffice-named styles. | [python-docx#1089](https://github.com/python-openxml/python-docx/issues/1089) (2022-05-28, open), [#967](https://github.com/python-openxml/python-docx/issues/967) (2021-06-25), [#504](https://github.com/python-openxml/python-docx/issues/504) (2018) | OOXML latent styles and theme indirection are only partially implemented. | Generated documents use explicit direct formatting for everything the content controls, so output does not depend on style-table inheritance; templates, if introduced later, are versioned and validated. |
| **Deck text overflows because autofit is metadata, not layout.** `TEXT_TO_FIT_SHAPE` only takes effect when a human opens the file in PowerPoint; there is no API to even know text overflowed. | [python-pptx#973](https://github.com/scanny/python-pptx/issues/973) (re-read 2026-10-10: closed "completed" — "nothing to be done" without a re-rendering pass), [#969](https://github.com/scanny/python-pptx/issues/969) (2024-04-25, open), [#1114](https://github.com/scanny/python-pptx/issues/1114) (2026-03-21) | Autofit scale factors are computed by the renderer, not stored. | Decks are generated with `fit_text(font_file=…)` using probed real font files so the stored sizes already fit, and slide structure previews surface long text instead of trusting the flag. |
| **Data mangling on export: dates arrive as "General", decimals stored as text, CSVs open garbled in Excel without a BOM.** | [pandas#59882](https://github.com/pandas-dev/pandas/issues/59882) (2024-09-24), [pandas#60230](https://github.com/pandas-dev/pandas/issues/60230) (2024-11-07), ChatGPT CSV/BOM guides (2024-10-15) *(search-derived)* | Cell type inference and charset sniffing. | Explicit cell types for every written value; identifiers that must keep leading zeros are written as text; CSV exports are UTF-8 with BOM and re-parsed before promotion. Regression: `tests/test_docgen_xlsx.py::test_cell_types_and_text_ids`. |

## 3. Rendering engines: conversion instability and fidelity lies

| Reported failure | Evidence | Mechanism | hutch answer |
|---|---|---|---|
| **LibreOffice headless: profile locks serialize the whole machine; long-lived listeners die or hang; big conversions time out.** One conversion process system-wide (2014); two concurrent instances corrupt the URP bridge, fixed by per-job `--env:UserInstallation` (2015–2018); unwritable HOME hangs conversions silently (2018); listener dead after ~3 weeks (2022); 5 MB+ conversions time out while small ones pass (2022). | [unoconv#225](https://github.com/unoconv/unoconv/issues/225), [#299](https://github.com/unoconv/unoconv/issues/299), [#449](https://github.com/unoconv/unoconv/issues/449), [gotenberg#516](https://github.com/gotenberg/gotenberg/issues/516), [gotenberg#407](https://github.com/gotenberg/gotenberg/issues/407) | Single-instance user-profile lock; unbounded per-document memory in a long-lived process. | If installed at all, LibreOffice runs per-job with a fresh `UserInstallation` profile, a hard wall-clock timeout, an owned process group killed on cancel/timeout, and a bounded queue; absence of the binary is a first-class readiness state (structure previews remain). Regression: `tests/test_docgen_render.py::test_soffice_timeout_kills_process_group` *(skipif no soffice)*. |
| **Silent font substitution reflows documents; non-embedded fonts break on other machines.** Substitutes have different metrics so documents "reflow badly" unless real fonts exist; substitution happens even when a metric-sibling is installed; complex-script conjuncts mangled; custom-font PDFs unopenable. | HN comments (2023-08-23, 2024-02-13) *(search-derived)*, [wkhtmltopdf#4949](https://github.com/wkhtmltopdf/wkhtmltopdf/issues/4949) (2021-02-09), [#4703](https://github.com/wkhtmltopdf/wkhtmltopdf/issues/4703) (2020-06-05) | Fallback matching on missing fonts; fonts not subset-embedded. | The generator probes installed fonts first and only uses fonts it verified (Liberation/DejaVu families on this host); PDF output embeds subsets automatically (WeasyPrint/fontTools); readiness reports the font set used. |
| **PDF engines blow memory on large documents, with per-version regressions.** A 220-page report needs ~2 GB; a 5,000-row table ~1.4 GB; leaks across renders fixed/regressed across versions (v62 fixed, v63 leaked ~2 GB over 10k renders). | [WeasyPrint#1950](https://github.com/Kozea/WeasyPrint/issues/1950) (2023-08-29), [#1104](https://github.com/Kozea/WeasyPrint/issues/1104) (2020-04-22), [#2130](https://github.com/Kozea/WeasyPrint/issues/2130) (fixed v62), [#2319](https://github.com/Kozea/WeasyPrint/issues/2319) (2024-12-03) | Whole-document layout in memory; engine-version regressions. | Rendering runs in a bounded subprocess (CPU/time/address-space limits) with a pinned engine version recorded in the manifest; oversized jobs fail with an honest size error instead of swapping the host. |
| **Wide tables clip in paged media.** Browsers are wider than PDF pages; unstyled wide tables overflow the sheet. Closed not-planned: fix your CSS. | [WeasyPrint#2417](https://github.com/Kozea/WeasyPrint/issues/2417) (re-read 2026-10-10: closed not-planned) | No auto-fit in pagination engines. | hutch's print stylesheet forces `table-layout`, wrapping, and font scaling for generated documents; the visual gate checks table boundaries. Regression: acceptance report artifact page checks. |
| **HTML→PDF engines are not sandboxed renderers.** Vendor guidance: untrusted HTML/CSS may cause long renderings, huge CSS values, and unwanted `file://`/network fetches; the HTTP timeout does not apply to `file://`; the same advice applies to untrusted SVG. | WeasyPrint `docs/first_steps.rst` security section (re-read 2026-10-10) | URL fetchers and CSS values are attacker-reachable surfaces. | PDF rendering accepts only hutch-authored HTML built from the typed content spec (never raw model HTML); a custom URL fetcher denies `file://` and all network; subprocess limits as above. |

## 4. Download-path robustness (web-app class)

| Reported failure | Evidence | Mechanism | hutch answer |
|---|---|---|---|
| **Non-ASCII / quote characters in `Content-Disposition` break or mangle filenames.** Several Nextcloud apps shipped unescaped filenames; quotes/backslashes needed a centralized RFC 5987 fix backported to three branches. | [nextcloud/server#59152](https://github.com/nextcloud/server/pull/59152) (2026-03-22), [#27354](https://github.com/nextcloud/server/pull/27354) (2021-06-02) | Header encoding divergence across browsers. | Filenames are served through Starlette's `FileResponse` filename handling (`filename*` UTF-8 + ASCII fallback), with the displayed name separate from the storage name; tests cover Unicode names. |
| **In-memory blob downloads fail on mobile Safari** (crash >3 MB, `blob.stream()` NPE, ~1 GB temp cap) and confuse users in SF View Controllers. | HN comments 2026-04-21, 2021-06-10, 2024-12-26 *(search-derived)* | Client-assembled blobs instead of server streams. | Downloads are plain navigations to streaming same-origin endpoints with Range support — no blob assembly in the download path. |
| **ZIP bombs / archive expansion.** A 42 kB zip expands to 5.5 GB; OWASP names the class but publishes no numeric thresholds. | [Fifield, "A better ZIP bomb"](https://www.bamsoftware.com/hacks/zipbomb/), [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) (both re-read 2026-10-10) | Trusting header sizes; unbounded extraction. | hutch-generated bundles cap entry count, uncompressed bytes, and path depth at write time; any future *import* path must count actual decompressed bytes (documented requirement, not yet implemented). |
| **CSV injection.** Historic OWASP guidance (prefix sanitization) has been removed from the Cheat Sheet repository (404, 2026-10-10); known criticisms: blocking leading `-` breaks legitimate negatives; filters evadable with `+`/tab/CR. | [OWASP CSV Injection sheet (removed)](https://cheatsheetseries.owasp.org/cheatsheets/CSV_Injection_Prevention_Cheat_Sheet.html), archive discussions *(search-derived)* | Spreadsheet applications evaluate leading formula characters. | hutch-generated CSVs contain only hutch-authored cell text; a defensive guard neutralizes formula-prefix cells and is disclosed in the format docs rather than silently altering data. |

## 5. Not adopted / honest limits

- **LibreOffice is not installed on the development host** (probed 2026-10-10: no `soffice`, Pango 1.58.2 present, Liberation + DejaVu fonts present). Office-format layout previews therefore ship as *structure previews* until an operator installs LibreOffice; the rendered-page path is implemented behind the readiness probe and marked implemented-but-unverified on this host.
- **Mammoth-style DOCX→HTML conversion and PDF.js in-app viewing were considered and deferred**: structure previews rendered by hutch's own UI code avoid serving active HTML in the app origin and avoid vendoring a large JS bundle into a no-build frontend.
- **Word/Excel/PowerPoint desktop compatibility, physical phones, and screen readers were not exercised** in this work; interop-sensitive output is validated by independent library re-opens and visual page inspection, which is weaker evidence and is labeled as such.
- Reddit and HN links marked *(not re-verified)* / *(search-derived)* were not fetched first-hand; they are directional, not load-bearing.
