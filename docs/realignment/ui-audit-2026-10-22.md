# Hutch measured UI audit and design review (2026-10-21/22)

## Scope and method

Base: `main@ceb9d36b` (after merging `wcag22-audit-fixes`). Work happened in an isolated worktree
on `agent/claude-wcag22m/measured-audit` and was compared against a frozen export of the base.
Both ran against isolated fixture servers seeded with clearly synthetic `mock/demo` data: 12
assistants (80-character, Arabic, Japanese, emoji and one-letter names), about 41 runs (long URLs,
mixed scripts, 220-character prompts) and pending approvals. No provider calls; no operator state.

Measurement came first; screenshots confirmed each finding:

- `ui-audit.mjs` (self-test passes; now runs axe-core 4.14.0 under Hutch's CSP) over 20 routes at
  320–1920 px with keyboard walks, plus text-spacing, pseudo-localization and RTL stress modes, and a
  sweep at 400–1280 px including ±1 px around the 640/900/1100 breakpoints;
- targeted probes for focus, overlap, CLS sources and keyboard paths, forced colours and benchmarks;
- a design-review instrument (text load, component fit, spacing, alignment) and a colour-vision
  simulation of the status palette (Machado 2009).

## What was wrong (highest impact first)

| ID | Impact | Evidence |
|---|---|---|
| F-01 | **No visible keyboard focus on most buttons** (Allow once, Deny, Review, Refresh…): an `all: unset` reset outranked the focus ring. Present since 2026-10-08; missed by earlier audits. WCAG 2.4.7. | Focused/blurred crops pixel-identical; computed `outline-style: none`. |
| F-02 | **Phone/tablet menu trapped keyboard focus** between Close and the logo; Chats, Needs you and the assistants were unreachable. WCAG 2.1.1. | Probe: 30 Tab presses alternate between two controls. |
| F-03 | Closed phone menu left ~20 invisible controls in the tab order before "Open menu". WCAG 2.4.11. | ui-audit focus-obscured (high) on every route at 320/375/768. |
| F-04, F-05, F-06 | The pending-work reminder covered the tablet header and the last "Show more" button; the chat header overlapped itself at 901–1440 px (switcher over the status chip; counts over Review/Stop). WCAG 2.4.11. | Screenshots and rectangle measurements. |
| F-18 | Keyboard focus on the reminder's Review button was destroyed every ~4.5 s by status polling. | Probe. |
| F-19 | In-sentence links distinguished by colour only. WCAG 1.4.1 (A). | axe `link-in-text-block`. |
| F-07–F-16 | Service names breaking letter by letter; Work history jumping on load (CLS 0.56); tables unreachable by keyboard in Safari; iOS zoom on focus; Activity showing storage IDs; empty headers; RTL overflow; 11 px text. | FINDINGS. |
| Tooling | `ui-audit.mjs` reported no axe problems because Hutch's CSP blocked axe and the error was swallowed. | 0 of 120 runs had axe results. |

## Design-level review (requested during the run)

- **Component fit:** immediate on/off settings were status text plus flipping Pause/Resume buttons
  (and one setting under two names); a single-choice filter was four toggle buttons.
- **Text load and breathing room:** helper text ran to 135–164 characters per line on wide screens;
  an empty section always shown in Needs you; Skills' header crowded (Refresh under the title, 0 px
  before the panel, touching buttons, mismatched control heights); 12 equal primary buttons on
  Manage assistants.
- **Colour and other disabilities:** under protanopia "Failed" and "Done" chips become the same
  colour (ΔE_ok 0.03) and shared the same dot.
- **Processing time:** notices vanished after a fixed 4.2 s, even under the pointer; the reminder
  stole focus as above.

## What changed

See [CHANGES.md](artifacts/ui-audit-2026-10-22/CHANGES.md) for the commit-by-commit table. In short:
restored focus rings; a keyboard-correct phone menu; a header that wraps instead of overlapping and a
reminder that docks below it (and never moves content); stable Work history loading; named,
focusable table regions; a 16 px touch-field floor; display names on Activity; reminder focus
preserved; underlined in-text links; a 72ch measure; a shared **switch** for "Automatic starts"
(Scheduled work and Runtime) and "Enter sends"; a radio-group filter; the empty bucket hidden;
notices that wait for reading; one primary action on Manage assistants; ✕ for failure; consistent
button-row spacing and aligned Skills controls; and the CSP-safe audit tool.

## User-facing change note

- **Scheduled work and Runtime:** "Pause/Resume scheduled work" and "Pause/Resume automation" are now
  one switch named **Automatic starts** (On/Off) on both pages. It does exactly what the buttons did.
- **Composer menu:** **Enter sends** is a switch (same setting, same default).
- **Work history:** the status filter is one Tab stop; use the arrow keys to change it.
- **Manage assistants:** each card's **Open** is now a secondary button; New assistant is the main
  action.
- **Status chips:** failures show ✕ instead of a dot.
- **Notices** stay a little longer and wait while you hover or focus them.
- **On tablets and laptops**, the chat header wraps its run controls onto a second row only when
  they do not fit, and the "N approvals need you" reminder docks below it.
