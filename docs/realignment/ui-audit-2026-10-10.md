## Findings

### [P2] Saved requests do not have typed placeholders

- **Location:** `src/hutch/server/static/app.js` saved-request library and composer insertion.
- **Evidence:** The owner can save, search, edit, delete and reuse a reviewed request in the local SQLite library. There is no typed
  variable or slash-command flow; the user edits the generated draft directly.
- **Category:** Implementation Integrity.
- **Impact:** Prompts with repeated fields still require manual draft editing; a hidden slash-command syntax could be hard to
  discover, so any future variable flow should have visible typed inputs and preserve the current no-send boundary.
- **Recommendation:** Add typed fields only if workflow research shows a real repeated-input need. Keep saved content owner-local,
  backed up, and explicitly reviewed before it is sent.
- **Suggested command:** `$impeccable audit` after any variable-insertion flow is implemented.

This is a bounded follow-up, not a failure in the verified saved-request or export/import paths. Open WebUI's current Workspace guide
documents typed prompt variables, slash-command insertion, and JSON import/export. Hutch's current library uses visible search and
direct draft editing instead of introducing implicit command syntax.

## Positive findings

- Frequent conversation actions stay visible; template, export and archive actions sit under one keyboard-operable More disclosure.
- A task template contains only the first user request and editable name. Assistant messages, tool output, files, account grants, and
  conversation identifiers are excluded.
- Import validates the declared format and bounds, changes only the draft, and does not trigger provider calls or create a run.
- Bot settings remain behind one options control per Bot; the compact large-roster flow stays searchable and keyboard-operable.
- Main-branch design roles are shared by generated app tokens and server-page CSS without replacing the established marketing layout.
