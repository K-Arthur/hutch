# WCAG 2.2 AA platform audit — Phase 1 (audit only, no code changed) — 2026-10-10

Baseline: **WCAG 2.2 Level AA** (the declared charter, `PRODUCT.md:86-88` and
`PRODUCT.md:119-125`). Scope: all three shipped surfaces — the SPA workspace
(`static/index.html` + `app.js` + `style.css` + `model-switcher.*`), the
server-rendered pages (`templates/` + `hutch*.css`: `/login`, `/pair`,
`/models`, `/usage`, `/legacy/*`), and the marketing site (`website/`).
Companion evidence: `artifacts/wcag22-audit/` (screenshots) and
`artifacts/wcag22-audit/measurements/` (raw JSON from every automated pass).

## How this was tested

| Method | What actually ran |
|---|---|
| Automated | axe-core 4.10.3 injected per page (tags `wcag2a/2aa/2.1aa/2.2aa`), Playwright **Chromium** on an isolated `hutch serve` at `127.0.0.1:18787` with seeded fixtures (3 assistants, 2 runs, 1 conversation, 1 pending approval) plus the genuine empty first-run state; marketing site served statically |

| Reflow | `scrollWidth` overflow check per route at 320 px and 200 % zoom; WCAG 1.4.12 text-spacing override stylesheet re-check (desktop + 320 px) |
| Target size | DOM sweep of every visible `button/a/input/select/summary/[role=…]` border-box per route, fine and coarse-pointer contexts |
| Contrast | Computed styles composited through canvas (alpha-correct, oklab-safe) for 20+ token pairs, placeholder, toast, focus ring |
| Keyboard | Scripted Tab sequences from clean loads (26 stops on chat), modal open→Tab-loop→Esc→focus-return, Needs-you dialog, model menu, skip-link activation |
| Behavior | Error-toast render/announce/dismiss, route-change focus + `document.title`, live-region audit by code review |

**Not performed** (so no claim is made about them): screen-reader output
(NVDA/VoiceOver/TalkBack — evidence here is accessibility-tree + keyboard
derived), physical iOS/Android hardware, `prefers-contrast` emulation,
performance profiling, WCAG user-spacing overrides beyond the 1.4.12 block.
Screen-reader claims in the prior audit (`ui-audit-2026-10-10.md:31`) remain
unverified after this pass; one manual VoiceOver spot check is recommended on
F-1/F-2 before merging Phase 2.

## Summary

**0 critical · 5 major · 5 moderate · 12 minor · 0 keyboard traps.**
The SPA routes pass axe with **zero violations at desktop and phone**; reflow
(320 px and 200 %), text-spacing, and every sampled contrast pair pass. The
real gaps concentrate in SPA route-change focus handling, two small pointer
targets, and inline link affordance on the auth/legacy pages.

## Findings — Major

### F-1 · Skip link is broken by the SPA router
- **Severity:** Major
- **WCAG:** 2.4.1 Bypass Blocks (Level A) — fail
- **Input:** keyboard / screen reader
- **Root cause:** `static/index.html:13` skip link targets `#view`; a hash of
  `#view` matches no route pattern in `route()`, which falls through to
  `location.hash = "#/chat"` (`static/app.js:1329`). The re-render discards
  the browser's focus attempt: after activating the skip link,
  `document.activeElement` is `BODY` (measured; `measurements/keyboard.json`).
- **Fix:** in `route()`, ignore hashes that are pure fragment targets (e.g.
  `if (!hash.startsWith("#/")) return;` before the fall-through), and have the
  skip link (or `route()`) explicitly call `view.focus()`; `#view` needs
  `tabindex="-1"` (`static/index.html:101`). Update
  `tests/e2e/test_browser.py` with an assertion that Tab→Enter on the skip
  link moves focus into `#view`.
- **Verify:** keyboard pass — first Tab focuses the skip link, Enter moves
  focus to `#view`, subsequent Tab continues inside the main content.

### F-2 · SPA route changes move neither focus nor `document.title`
- **Severity:** Major
- **WCAG:** 2.4.2 Page Titled (A) — static title across views; 2.4.3-order /
  screen-reader orientation (best practice for SPAs)
- **Input:** screen reader / keyboard
- **Root cause:** `route()` (`static/app.js:1304-1330`) swaps `#view`
  innerHTML and never relocates focus; `document.title` is static
  (`static/index.html:6`). Measured: after `#/chat → #/overview`, focus stays
  wherever it was and the title is unchanged. View headings live in
  `#app-top-context` (e.g. `<div class="ctx-id"><h1>Activity</h1></div>`),
  not inside `#view`.
- **Fix:** after the view handler resolves, focus the new view's heading
  (`#app-top-context h1`, with `tabindex="-1"` added when rendered) or `#view`
  itself, and set a per-route `document.title` (small route→title map in
  `route()`). Keep the existing meticulous in-view focus management intact.
- **Verify:** AX-tree snapshot before/after navigation shows the announcement
  point at the new view; title changes per route; no focus loss.

### F-3 · Toast dismiss control is 16×16 px and is the only way to close error toasts
- **Severity:** Major
- **WCAG:** 2.5.8 Target Size (Minimum) (AA) — fail (24×24 minimum; no
  spacing/equivalent/inline exception applies: adjacent `toast-msg` is not a
  target, errors persist until dismissed, `app.js:466-467`)
- **Input:** touch / motor-impaired pointer users
- **Root cause:** `.toast-close { all: unset; … }` sets no size
  (`static/style.css:1474`) and `icon()` renders 16×16 SVGs
  (`static/app.js:639-640`). Measured box: 16×16
  (`artifacts/wcag22-audit/error-toast-phone-390.png`).
- **Fix:** give `.toast-close` `min-width/min-height: 24px` (44 px inside
  `@media (pointer: coarse)`), padding to preserve layout, keep `all: unset`
  only for the cosmetic reset.
- **Verify:** re-measure rendered box ≥24 px (≥44 coarse); axe target-size
  re-run with a toast open.

### F-4 · Inline links on `/login` and `/legacy/*` are distinguished by color alone (1.74:1)
- **Severity:** Major
- **WCAG:** 1.4.1 Use of Color (A) — fail (axe `link-in-text-block`, serious);
  1.4.3 contrast to the page background passes (≈7.7:1 emerald)
- **Input:** all (low-vision and color-blind users most affected)
- **Root cause:** "Pair this device" (`templates/login.html`) and the
  "preview limits" link (`legacy/connections`) render with no underline and
  emerald `rgb(52,211,153)` against gray body text `rgb(125,142,164)` — a
  1.74:1 difference from surrounding text (measured,
  `measurements/fixups.json`).
- **Fix:** add `text-decoration: underline` for in-text links on server pages
  (or an underline on hover+focus plus a brighter link color ≥3:1 vs body
  text). Match the SPA's existing `.inline-link` treatment where it already
  passes.
- **Verify:** axe `link-in-text-block` re-run on `/login`, `/pair`,
  `/legacy/connections`, `/models`, `/usage` returns clean.

### F-5 · Workflow status pill is a 81×16 px pointer target with no equivalent
- **Severity:** Major
- **WCAG:** 2.5.8 Target Size (Minimum) (AA) — fail (h=16; the pill is the
  only persistent link to `#/approvals` — `app.js:1880` — so no equivalent
  exception; hidden on phones ≤900 px, `style.css:1820`)
- **Input:** mouse (desktop only)
- **Root cause:** `a.w.needs` is an inline status pill in `.app-top-status`
  with line-height-sized box (measured 81×16 on every desktop route).
- **Fix:** pad the `.workflow a` links to ≥24 px box (`padding: 4px 0` +
  negative margin to keep layout), or make the whole `.workflow` line a
  target.
- **Verify:** re-measure ≥24 px on desktop; confirm phone layout unaffected
  (element hidden there).

## Findings — Moderate

### M-1 · Tool-stream disclosure summary is 22 px tall (coarse rule misses it)
- **Severity:** Moderate · **WCAG:** 2.5.8 (AA) — fail (h=22<24, no
  exception: full-width standalone control, no spacing clearance)
- **Input:** touch / all pointer
- **Root cause:** `.tool-stream > summary` has `padding: 0`
  (measured 712×22 desktop, 366×22 coarse); the coarse sizing rules target
  `.tool-line-head` (`style.css:1838`) but this summary carries no class.
- **Fix:** add padding (`10px 0`) to the tool-stream summary, desktop and
  coarse. **Verify:** re-measure ≥24 px (≥44 coarse) on `#/chat/…` with a
  tool stream present.

### M-2 · `.btn.small` stays 26 px tall on touch pointers (Stop/Remove/Review inline actions)
- **Severity:** Moderate · **WCAG:** 2.5.8 AA — pass (26>24); **product
  charter miss** (`PRODUCT.md:86-88` 44×44 comfort target)
- **Input:** touch
- **Root cause:** specificity — `button.small { min-height: 26px }`
  (`style.css:462`, 0,1,1) beats the coarse `.btn { min-height: 40px }`
  (`style.css:1833`, 0,1,0). Measured 26 px under `pointer: coarse`
  (`measurements/followup.json`).
- **Fix:** inside the coarse block use `button.small, .btn.small {
  min-height: 44px; padding: 0 var(--s-3) }` (0,2,0) to win.
- **Verify:** coarse-context measurement ≥44 px on `#/approvals` review rows
  and the execution-hold bar.

### M-3 · Assistant-settings hints are not programmatically associated
- **Severity:** Moderate · **WCAG:** 3.3.2 Labels or Instructions (A)
- **Input:** screen reader
- **Root cause:** template fields use visual `<small>` sibling hints without
  `aria-describedby` (pattern at `templates/bot.html:71`); same for several
  SPA render paths (`app.js` settings forms).
- **Fix:** wire each hint/error `<small>`/`<p>` with an id and
  `aria-describedby` on its input (repo already does this 22× elsewhere —
  extend the pattern). **Verify:** AX tree shows describedby on settings
  inputs; axe passes (it cannot catch this — manual/tree check required).

### M-4 · `/legacy/runs` renders with empty `<title>` and no `lang`
- **Severity:** Moderate · **WCAG:** 3.1.1 Language of Page (A) — fail;
  2.4.2 Page Titled (A) — fail (axe: `html-has-lang`, `document-title`)
- **Input:** screen reader / all
- **Root cause:** the legacy runs template renders outside `base.html`
  (measured, `measurements/axe-desktop.json`).
- **Fix:** route the legacy template through `base.html` or add the missing
  `<html lang="en">` + `<title>` directly. **Verify:** axe re-run clean.

### M-5 · Approval review rows keep a fixed 140 px label column at phone widths
- **Severity:** Moderate (usability friction; 1.4.10 itself **passes** —
  measured zero horizontal overflow at 320 px because `minmax(0,1fr)` absorbs
  the shrink)
- **Input:** touch
- **Root cause:** `.review-row { grid-template-columns: 140px minmax(0,1fr) }`
  (`style.css:1115`) never collapses; values wrap hard at 320 px.
- **Fix (needs product/design input):** stack label above value ≤480 px, or
  accept the cramped two-column — flag for sign-off rather than assume.
- **Verify:** 320 px capture before/after (`approvals-phone-390.png`).

## Verified non-issues (tested clean — worth recording)

- **axe-core: zero violations** on every SPA route (desktop + phone), `/pair`,
  `/models`, `/usage`, marketing. Only F-4/M-4 flag on server/legacy pages.
- **Reflow 1.4.10:** zero horizontal overflow on all 11 SPA routes at 320 px
  and at 200 % zoom; **1.4.12 text-spacing** override produces no overflow
  (flagged "clipped" elements were the intentionally off-canvas phone nav).
- **Contrast:** all sampled pairs ≥6.09:1 (`.hint` 6.09, chips, nav 10+,
  placeholder 6.09, toast 16.4, marketing muted 8.88); token pipeline already
  enforces declared pairs. The 1.33/1.74-looking focus-ring/nav values in the
  raw JSON are artifacts of a semi-transparent background walker, not real.
- **Focus visibility 2.4.7:** 2 px `#60a5fa` outline + offset on links,
  buttons, summaries; inputs use border+ring replacement; `forced-colors`
  block present.
- **Keyboard:** no traps anywhere; modal (aria-modal, labelledby, initial
  focus, Tab-wrap, Esc → focus back on trigger), Needs-you native `<dialog>`
  (Esc, focus return verified), model menu (roving focus, Esc), roster menus,
  composer menu — all exemplary. Clean tab order = DOM = visual order with
  proper accessible names ("Options for Scout", "Needs you 1").
- **Viewports:** zoom never disabled (1.4.4 pass); `dvh`/safe-area handling
  throughout; composer clears the virtual keyboard.
- **States:** loading (spinner + text), error (`errorState()` with recovery
  link), empty first-run welcome, execution-hold, paired-phone offline — all
  carry text, not color alone.
- **Forms:** labels complete (explicit + wrapped), sensible
  `autocomplete`/`inputmode`/`type`; OTP field exemplary.

## Known limitations / not addressed

- No screen-reader or physical-device evidence (see "How this was tested");
  F-1/F-2 need one VoiceOver/NVDA spot check by a human before merge.
- Performance-as-accessibility not profiled this phase.
- Third-party surfaces (OAuth provider screens, provider dashboards) are out
  of the repo's control — noted, not audited.
- i18n/RTL: English-only product; localization would require a layout pass
  (physical `left/right` properties dominate the CSS).
- At baseline, M-5 needed a product decision (stack vs. cramped two-column);
  current implementation stacks the rows on phones (see follow-up below).
- Recommend (separate decision): a permanent axe pass in e2e (the harness in
  this audit is ad-hoc; repo currently has no a11y CI gate).
