## 1. How to use this matrix

Gate rules for reviewers and implementers:

1. A row is gate-complete only when all of these exist: distinct state IDs implemented; recovery action implemented; hostile test data in a deterministic fixture; required evidence recorded; a named slice owner; and a verdict of IN (or an explicit OUT/NO-OP that is not built).
2. A generic state named "error", "failed", "something went wrong", or "no service" is not acceptable anywhere. Each row's state column names the distinct states that must be rendered and announced.
3. "Saved" is not "verified". Only a real provider call or a real first generation may produce the verified state (FM-02, FM-12; R3:130,140).
4. Provider-unavailable, permission-denied, offline/local-server-unreachable, and stale-resume must stay four separate families. Collapsing any pair is a review failure even if the copy is friendly.
5. Missing evidence is FAIL, not a partial pass (VV:102). A browser, screen-reader, or real-phone check may not be claimed unless it was actually run in the lane described in section 10.
6. An OUT row may not be implemented "while we are here". It re-opens only through the recorded re-open condition, at which point this matrix is revised and the new evidence is required.
7. Every IN row maps to at least one planned slice 01-11 (section 3). Cross-cutting rows legitimately map to several.

Reviewer outcome per row: PASS only when the state vocabulary, recovery, data, evidence, and slice are all present and testable; otherwise NEEDS WORK with at most three findings.

Hard separations that must be visible in copy, announcement, and tests:

1. Provider unavailable vs permission denied: provider.unavailable (5xx/transport/deadline), provider.permission_denied (403 or upstream policy block), provider.invalid_credential (401 after trimming), provider.no_credit (402), provider.rate_limited (429 with Retry-After).
2. Provider vs local server vs network: provider.unreachable, server.unreachable (local Hutch process stopped), local.unreachable (local model service down), net.offline (client offline), local.no_model (service up, zero models).
3. Session expiry vs credential failure: auth.session_expired and auth.csrf_rejected must never render provider wording; provider.invalid_credential must never render sign-in wording.
4. Stale resume vs expired wait vs partial save: setup.resume.stale, wait.expired, setup.draft.partial are three different states with three different next actions.
5. Saved vs verified: setup.saved_unverified must not use the word "connected" or a success colour; verified requires a real provider call or first successful generation.
6. Duplicate suppressed vs error: submit.duplicate_suppressed means the server returned the stored result; show "already saved" and the existing object, not an error.
7. Blocked vs disabled: setup.blocked_external_action names the blocker and the one next action; a disabled control never stands in for a blocked explanation.
8. Optional vs incomplete: step.skipped is success-with-deferral; setup.complete_with_skips is a valid completion.
