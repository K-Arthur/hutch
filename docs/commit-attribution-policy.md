# Commit attribution policy

Commits in this repository are authored by the maintainer, not by the tools used
to make the change. This page defines the rule, how it is enforced, and how to
repair a commit that breaks it.

## Rule

- Commit messages must not carry AI attribution. No AI tool, assistant, agent,
  bot, model or vendor may appear as author, co-author, committer or in a
  generated-by / created-by / written-by / assisted-by signature, unless the
  maintainer explicitly requests that attribution for a specific commit.
- Commits keep the maintainer's configured human identity as author and
  committer. Do not set an AI identity through environment variables, git
  configuration or commit flags.
- Mentions of AI products, models and vendors in documentation, code and commit
  body prose are fine. The rule targets attribution syntax, not the subject
  matter: a commit that describes the Claude API or the OpenCode runtime is
  legitimate.
- Keep legitimate collaboration trailers: human co-authors, Signed-off-by,
  Reviewed-by and Tested-by.
- The rule applies to new commits. Published history is never rewritten as part
  of this policy without explicit maintainer coordination: commits already on
  public refs keep their original messages, and the enforcement below only
  scans new commit ranges. Unpublished local commits may be reworded before
  they are first published; the checker's --range mode verifies such a range.

## Enforcement

Two gates apply the rule automatically:

1. Local commit-msg hook: .githooks/commit-msg runs
   scripts/check_commit_attribution.py against the candidate message before the
   commit is created. Enable it once per checkout:

       git config --local core.hooksPath .githooks

   That setting also enables the repository's pre-commit hook, which runs the
   repository hygiene check and requires Gitleaks 8.30.1 on PATH.
2. CI: the "commit attribution policy" job in .github/workflows/ci.yml scans
   only the commits added by a pull request (merge-base..HEAD) or a push
   (before..HEAD). It never scans the preserved historical commits outside the
   range. The job runs only for the public repository copy.

Hooks can be bypassed with git commit --no-verify, and some GUI or automation
clients skip them. CI is the backstop for those paths.

The checker itself can be run directly:

    python3 scripts/check_commit_attribution.py --message-file .git/COMMIT_EDITMSG
    python3 scripts/check_commit_attribution.py --range origin/main..main

It exits 0 when clean, 1 when attribution is found and 2 on a usage or git
error. Only attribution syntax is flagged: an AI-named Co-Authored-By trailer,
an AI-keyed trailer such as "Claude-Session: ...", a trailer carrying an AI
coding-session link (claude.ai/code/session, chatgpt.com/c/, a Cursor session
link), a generated/created/written/assisted/made-with signature naming an AI
tool, or an explicit AI-generated signature. Ordinary prose and automation
notices such as "Generated by scripts/generate_agent_map.py" are allowed.

## Fixing an accidental trailer

- If the commit is not published yet, amend or reword it locally
  (git commit --amend, or git rebase -i against the last published commit) and
  rerun the checker on the range.
- If the commit is already published, do not rewrite published history as a
  side effect of this policy. Coordinate with the maintainer first and treat a
  force-push as a separate, explicitly approved operation.
- Never strip human co-author, Signed-off-by, Reviewed-by or Tested-by trailers
  while repairing a message.

## Client-side defaults

The observed trailers came from AI client defaults, not from repository files.
Where a client supports it, switch attribution off at the source as well:

- Claude Code: set `"includeCoAuthoredBy": false` in `~/.claude/settings.json`
  (the embedded default is true).
- Cursor CLI: set `attribution.attributeCommitsToAgent` and
  `attribution.attributePRsToAgent` to false in the CLI configuration
  (commit attribution defaults to true).
- OpenCode: no local attribution setting was found; rely on this repository's
  hook and CI for commits made here.

These are user-level settings outside the repository and are not enforced by
the repository's gates; they are documented so each checkout can stop the
attribution at its source where the client allows it.

## Exceptions

An exception requires the maintainer's explicit request for a specific commit.
Because the hook and CI enforce the rule without a bypass flag, an approved
exception is implemented by changing this policy and the checker's detection
rules in a reviewed commit; the normal local and CI gates stay in place until
that change lands.
