# Marketing site claims and evidence

The static site is an alpha preview, not an installation or hosted-service funnel. Its source repository is private and there is
no public package or release. The anonymous page therefore points its calls to action to local sections that show the demo and
availability status; it does not send visitors to a private GitHub repository, copy commands that cannot work anonymously, or
contact the Hutch host. The site loads its CSS, JavaScript, font and images from its own directory. The only persistent browser
preference is the effects setting in `localStorage`.

## Capability language

The State specification now describes database-only snapshots and held restoration into a new
directory. It explicitly excludes credentials, browser profiles and user files. Local fixture
tests cover current/legacy database restoration and an active source PID; this does not certify
production cutover, restore browser sessions or roll back external effects. The marketing site
does not call the new state commands, expose private reports or gain executor access.

| State shown publicly | Evidence and limit |
|---|---|
| Supported | Linux execution, local SQLite state, deterministic offline mock and fixture-tested lifecycle/API paths. This does not imply a public download or production service. |
| Experimental | Configured hosted-provider and local-inference routes, with one Hutch local caller and up to eight waiters per state directory. Provider HTTP behavior has fixture coverage; no paid provider or real Ollama model was exercised for this release. |
| Unavailable | macOS/Windows executor, public source/package, remote phone control, browser handoff, OpenCode/Pi harness execution and Sign in with ChatGPT. |

The site distinguishes the control state kept on the host from prompt traffic to a selected model and network traffic generated by
tools. A local or loopback endpoint does not prove that its backend stays offline. Native Ollama admission
uses current memory measurements and backend-reported resident allocations; footprint/context fit
remains an estimate. Other local protocols do not yet have validated memory admission. Hutch reserves token and price estimates before eligible hosted calls. Those estimates are not guarantees of provider
invoices; operators should use provider-side billing controls for external spending limits. Bubblewrap is an optional Linux
namespace sandbox, not a VM; migrated bots remain unsandboxed until an operator enables it.

## User-report scenarios

The receipts section links directly to three public issues used as acceptance scenarios, not as prevalence evidence:

- [OpenClaw issue 138499](https://github.com/openclaw/openclaw/issues/138499): one report of a timed-out scheduled task remaining marked as running and delaying restart. Hutch tests keep cancellation visible until owned execution exits and fence expired ownership before recovery. The report itself says its reproduction conditions were not sufficiently deterministic.
- [Open WebUI issue 30055](https://github.com/open-webui/open-webui/issues/30055): one report that a full-screen mobile call overlay hid an already-delivered approval. Hutch keeps approval state and decisions in the responsive app and fixture-checks phone layouts; this is not a physical-device certification.
- [Open WebUI issue 31656](https://github.com/open-webui/open-webui/issues/31656): one report that mobile menu focus opened a text field and keyboard unexpectedly. The Hutch menu uses dialog focus, Escape and focus restoration checks. This is keyboard/viewport coverage, not a screen-reader audit.

The site intentionally removed unattributed forum IDs, unsupported spend-guarantee language, claims that every path is jailed, dead public-install links and claims that disabled external harnesses are supported.

## Conversation-first interface

Product copy describes decisions in chat and the cross-bot Needs you drawer; it does not promise
that a separate Approvals page is required. Activity and run history are monitoring tools, and
Fleet is progressive navigation at ten bots. The threshold is a product heuristic, not a measured
user-research result. Sanitized captures are refreshed from isolated deterministic mock state;
no executor credentials or localhost requests are added to the static site.

Schema-v11 replay strengthens local chat/attention recovery and has viewport/browser fixtures.
It does not change the site's remote-phone-control or provider support labels. New inspected
captures in `realignment/artifacts/resource-replay/` demonstrate local admission and draft
preservation; they are not physical-device or live-provider evidence. The four original site images retain
their separately recorded navigation-capture provenance in `results.json`. They were
refreshed from that capture, while public support labels retain the same limits.

Schema v12's inspected file-error views show the database answer and completion remaining
available while audit-file delivery retries. This strengthens local persistence evidence;
it does not add remote control, provider or physical-device support claims.
